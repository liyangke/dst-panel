# DST 面板

饥荒联机版（Don't Starve Together）专用服务器的自托管管理面板。一个 Go 二进制，把开服、模组、存档、日志、玩家状态和面板设置收在一个网页里；部署在和服务端同一台机器上，手机浏览器也能用。

- 后端：Go 1.23 + 标准库 `net/http` + SQLite（`modernc.org/sqlite`，无 cgo）
- 前端：免构建 Vue 3（vendor 里的 global 构建）+ 手写 CSS，静态资源 `go:embed` 进二进制
- 进程：靠 `screen` 会话启停 DST 分片，面板重启不影响已经开着的服
- 数据通道：自写助手 MOD 读写 `save/` 下的 JSON 文件，回传在线玩家、世界状态，按需导出地形与建筑/资源底图

| 游戏日志 | 两种看法。**玩家事件表**（默认）：把同一个世界的两份日志合起来，一行一记行为（进服/死亡/消散/复活/离开/暂时走开/回来/被请下线/被封禁/发言），每行尽量把这个人在本轮里已知的身份补齐——显示名、角色（头像上是短名）、账户编号、Steam ID、来源 IP，查得到才写，查不到留 `—`，绝不把别人的 IP 安到她头上；筛选（人/动作/关键词/回看行数/每页条数/发言开关）与分页全在后端，所以底部那句"第 1–20 条 / 共 312 条 · 涉及 6 个人"说的是真的发出去的东西，九列还能各自关掉（固定那四列除外），点「看原文」跳到逐行日志并带着这一记的条件过去，点「拉黑」写进这个房间的 `blocklist.txt`。**逐行日志**：实时 SSE 跟随，按房间/世界/等级/事件/关键字筛，事件短名选中后展开整句说明 |
| 任务中心 | 异步任务队列：进度、失败原因、取消、重新提交。下载/更新本体的进度条是**整包字节进度**，条下面四个数（已下 / 整包 / 速度 / 还要多久）全部从 steamcmd 的输出里实测，一个都不是估的；一旦读到整包大小就不再听 steamcmd 自己那列百分比（它量的是"这一步状态机走到哪"，跟着走会出现"已下 201 MB / 4.3 GB（18%）"这种自相矛盾的话）；steamcmd 在校验已下载文件时字节量也在涨，那一段界面换成"已处理 / 吞吐"，不冒充下载。卡死靠"连续几分钟读不到新内容"判，不靠墙钟，见下面第 5 条取舍 |
| 操作记录 | 谁在什么时候改了什么、成功与否、失败原话；按动作族筛选 |
| 房间归属（多租户） | 管理员把某个房间指派给某个成员账号：成员看到的房间名单只剩「自己名下的 + 还没指派的」（在接口响应里就裁好，不是前端拿到全部再藏），没指派的那几间他看得见状态但改不动；派给只读账号、派给管理员、名下还有房间就把它改成只读，这三种都会被接口拒并说清该怎么办；操作记录和任务中心也按归属收窄。入口两处：总览那张房间卡上那枚「指派」管眼前这间，「账号管理」下方那张「房间归属」一次列全这台机器的房间和归属（#129 之前它住在「所有房间」那一页，那一页已整页下掉；用的就是外壳每五秒取回的那份名单，不另扫一次盘） |
| 账号管理 | 面板多账号：新增/停用/删除、改密码，角色分「管理员 / 房间成员 / 只读」三档；还在用出厂默认密码的账号会被标出来，短密码当场提示 |
| 面板设置 | 操作记录/趋势保留天数、快照保留份数、定时备份间隔，改完立刻生效 |

前端按 390px 宽的手机屏单独排过：日志筛选默认折叠、表格在手机上换成卡片、次要信息下沉、触控目标不小于 36px，没有横向滚动。深浅双主题。窄屏下模组检索是两列卡片，1440px 是五列，都是真实 Chrome 按视口量出来的。

### 待办提醒、任务入口与在线趋势图（2026-11-09）

- **「待处理提醒」只在总览「下一步」说一遍**：默认密码、缺服务端本体这两条不再各画一种横幅，也不在别的页正文顶部铺「摘要行 + 展开清单」那一大块（2026-11-09 第二轮，用户："总览页面，下一步的卡片已经展示了这些信息，其他页面还需要如图这个吗？看上去很丑"）。条目定义只有一份（`internal/webui/assets/js/pending.js`），总览那张卡渲染同一套「图标 / 说明 / 动作」行（`.step-row`）。别的页只在**顶栏留一枚「待办」入口**：有条目才出现，显示的数字直接取与总览卡同一份清单的长度（2026-11-09 第四轮把两处统一到 `checklistRows` 一个函数，不再各数一份），明细放悬停，点一下带 `#/?focus=todo` 回总览并高亮那张卡，首屏完全让给本页内容。390px 顶栏本来就挤到刚好，这一枚收进「更多」抽屉、换成带文字的按钮，顶栏标题不再被压成省略号。只读账号同样看得见这张卡（安全提醒不挑角色），但动作那一格统一换成「需要管理员处理」，不摆点了也没用的按钮。`.tools/ui_checklist_check.py` 的判据同步改成：总览与别页正文里 `.warnbar / .pending-list` 都是 0 块、顶栏 `button.gauge.todo` 存在且点得动、只读账号看得见卡但行内 0 枚按钮。
- **总览不再铺「未结束的任务」卡**：顶栏那枚「未结束任务」实时计数、点一下直达任务中心，那一页本来就有进度条、字节明细、提交时间和操作；总览那张卡只在恰好有任务在跑时才有内容，平时是一整块「暂无进行中的任务」占掉右半幅，属于同一件事说两遍。现在整张删掉，「这台机器」一张卡横跨整幅（`.host-row` 单列，卡内环与明细表按宽度均分），顶栏仪表的悬停补上"只数下载/更新本体、备份、恢复、导入这四类耗时操作；模组下载与世界启停不进这个数"的口径。`.tools/overview96_check.py` 与 `.tools/overview105_check.py` 的判据从「两张卡并排、缝隙 ≥8px、右卡空态与气泡」改成「没有 `.host-live` 残件、这一行只剩一张卡、卡横跨整幅、顶栏入口可点且悬停带口径」。
- **在线情况图不因人数恒定而消失**：这一窗每个采样点都是同一个人数时，折线、面积和 0 起点纵轴照常画——平线本身就是「这段时间一直是 N 人」，图下只补一句短说明；以前用一段文字把整张图换掉，用户会以为图坏了或没采到数。图场 180px、0 起点纵轴这些判据一条没动。
- 顺带修掉 `ui_audit` 第十一条报出的 `bulkBusy()`：模组页批量按钮写成函数调用，没勾行时被短路挡着不发作，一勾就抛 "not a function"，现按 computed 值读。

### 总览版式、控件与多玩家（2026-11-09 第四轮 + 第五轮）

- **卡片顺序按"要不要催人做事"分开排**：用户问「下一步和这台机器这两个卡片，应该是放在底部好，还是顶部好」。「下一步」是整机级、会催人做事的清单（默认密码、缺服务端本体、没房间、缺令牌、助手不回话、没备份），提到**页顶**：判据不随页签选中的房间变，压在房间卡下面会被读成"这间房的事"，顶栏「待办」点进来也不必再长距离滚到页底；「这台机器」是低频、只读、数值密的诊断卡，留在**整页最下面**（展开时三枚环 + 明细约 250px，放页顶会把"在不在跑、几个人在线"挤出首屏）。中间仍是房间页签 + 实况 + 两张图。
- **没有待办时不白占首屏**：清单为空时 `.next-steps.is-quiet` 把卡头整块收掉，只留一行「都齐了」，有待办时自动摊回整张卡。同时去掉外层 `.col` 上那三个 `style="order:…"`——原先 DOM 是「下一步 → 这台机器 → 房间」、视觉却是「房间 → 下一步 → 这台机器」，键盘 Tab 与读屏顺序是反的；现在 DOM 顺序 = 视觉顺序。
- **顶栏待办重新显示数字，口径与卡片一致**：用户「我还是希望能显示数字，他的口径和卡片栏里的待办一致即可」。原来顶栏只数 `/session` 给的两条全局提醒、卡头还含机器现状核对出来的条目，两个数字对不上；现在清单计算（`js/pending.js` 的 `checklistRows`）与取数（`js/store.js` 的 `state.checklist` / `loadChecklist`）都搬到全局，顶栏与卡头读同一个数组，390px「更多」抽屉里那枚入口也显示同一个数。取数由登录时和每四次轮询各触发一次，`loading` 去重，只读账号不扫盘。
- **次要按钮不再是深色实心块**：用户截图指出「按钮都是黑色的，我感觉不是很搭配？有点粗糙」。`.btn` 改成半透明浅底 + 细描边 + 主文本色，悬停才浮出主色；浅色主题另给一层实心 `--card-2` 浅灰底和稍深的边（纯透明底在白卡上几乎看不见）。`primary / danger / ok` 仍各自盖得住自己的底色，危险按钮悬停不会变成蓝的。
- **删掉说明气泡与口径文字**：用户「这一张怎么读，这些数怎么来等等，我觉得完全没必要」「这台机器里得口径，我也觉得没必要」。总览页 6 处带标签的 `x-hint`（这一档怎么读 / 这一张怎么读 ×2 / 这几条怎么来的 / 这些数怎么来的 / 完整口径说明）、只服务气泡的 `trendNote` / `behNote` / `metricsText` 三个 computed，以及「这台机器」底部那行常驻「口径：磁盘与网络是整机读数…」全部下掉；指标本身与行内悬停解释还在，口径要看去接口或文档。**别的页面同类标签本轮没动**。
- **多角色不再靠"把卡压窄 + 封顶滚动"硬塞，改成按人数换形态**（第五轮，用户「既然多个角色会乱，你打算怎么解决」→「按你说的做」）：第四轮做过两层治标——`.detail-players` 从 `.grid-cards` 的 320px 下限收到 `minmax(200px, 1fr)`（1440 / 768 的 6 人都是 3 列 × 2 行，网格 344 / 381px），`.shard-detail` 封顶 `max-height: 420px; overflow-y: auto`；但 390 上 6 人内容 1075px / 可视 418px，只看得到两张多、其余要在这格里滑好几屏，人数再多或名字一长照样挤。根子是**富信息卡的信息密度固定、人数却不定长**。现在 `views/overview.js` 的 `playerMode` 按 `players.length` 分三档：
  - **≤4 人**保留富卡网格——三条三围竖排，人少时横向比"谁快饿死了"最有用，别动；
  - **5–8 人**换成 `.player-roster` 一行一人（头像 + 名字 + 角色 + 三段等宽细条，单条 36px，6 人一屏读完、不用滚动）；三段位置逐行对齐，纵向仍能在人与人之间比同一条；坐标、物品数与三围精确值收进整行悬停，不占高度；
  - **>8 人**先只报「N 人在线」+「展开名单」，展开后仍是紧凑行，人数再多也不会把房间卡撑爆。420px 上限降级为这一档展开后的兜底。
  助手没采到某个三围时接口给 `null`，紧凑行画成淡底全宽、悬停写「未知」，不画成 0%（那会读成"快饿死了"）。摘要条是带 `aria-expanded` 的 `button`，键盘与读屏可用；390 把角色名那列让出来给名字和三围，角色仍在悬停里。
- 验证：`.tools/player_modes_check.py` 是这一档的常驻探针——**改磁盘上的助手快照 → 后端每次 `/status` 重读 → store → Vue**，走和真实进服的人同一条链路；7 档人数（1/4/5/6/8/9/12）× 3 视口 × 深浅主题，逐档验形态、行数、三段三围、null 淡底、6 人整格不滚动、>8 默认收起与展开/收起、横向溢出，跑完自动还原快照（后面的脚本都按"地表 2 人、洞穴 1 人"写断言）。`.tmp_boot/check134.py` 原来那段 `cloneNode` 造 6 人已撤：**克隆 DOM 不会让 Vue 按人数重算 `playerMode`，留着只会验到一张假的富卡网格**，它现在只管顺序、顶栏与卡头数字、说明气泡数、口径行、按钮底色与空态收起。其余 `ui_audit.py`、`ui_checklist_check.py 1440`、`overview96_check.py`、`overview105_check.py`、`js_error_sweep.py` 390/1440 两档 12 页、`go build ./...` + `go test ./...` 全绿。

## 它是怎么跑起来的

```
 浏览器（PC / 手机）
      │  HTTP Basic + JSON / SSE
      ▼
 ┌──────────────┐   SQLite（任务、审计、趋势、设置）
 │  dstpanel    │──────────────┐
 └──────┬───────┘              │
        │ screen -dmS / stuff  │ 读写文件
        ▼                      ▼
 ┌──────────────┐      ~/.klei/DoNotStarveTogether/
 │ screen 会话  │        Cluster_x/ Master|Caves/
 │  dst-<集群>  │◄────►  cluster.ini、server.ini、
 │  -<分片>     │        worldgenoverride.lua、
 └──────┬───────┘        modoverrides.lua、
        │                save/
        ▼
 DST 专用服务端（bin64/dontstarve_dedicated_server_nullrenderer）
        │
        ▼
 助手 MOD：每秒写 status.json，从 command 队列取命令
```

关键设计取舍：

1. **为什么用 `screen`**：面板自己需要升级重启，而游戏服不能跟着断。分片跑在独立 screen 会话里，面板退出/重启只是看不到它，进程还在。
2. **为什么助手 MOD 走文件**：DST 服务端不暴露 RCON 之外的结构化接口，而 RCON 要额外开端口、还要处理协议。MOD 在游戏进程里能拿到最准的数据，把 JSON 写进 `save/`，面板直接读，不需要额外监听端口。
3. **为什么前端不打包**：静态文件内嵌在二进制里，`go build` 一次就得到可部署产物；没有 npm、没有构建缓存、没有版本漂移。代价是不能用 SFC/vue-router，用字符串模板和一百多行的 hash 路由补上。
4. **为什么异步任务**：SteamCMD 首次下载整包 4.28 GB（实测那行括号里是 `4594664662`），同步 HTTP 请求会被反代和手机浏览器掐断。入队后由 worker 串行执行，进度写库，页面轮询；每个任务都记录尝试次数和失败原话。进度数字只从 steamcmd 自己那行 `progress: X (已下 / 整包)` 里读，速度用相邻采样点的字节差算，所以换一台带宽不同的机器数字自己会变，界面上没有任何写死的大小或耗时。
5. **为什么判停靠"有没有在动"而不是靠时间**：同一台 4 核 4 G 云机、同一次任务里量到相差五百倍的带宽——本体文件下来那一段 9.9–29.6 MB/s（4.28 GB 用 4 分半），steamcmd 给自己更新那一段约 115 MB 跑了 34 分钟（中途 30 秒窗口只量到 33 KB/s）。任何按"典型带宽"写死的墙钟上限都会在某台机器上把正常下载判成失败，所以真正的判停是"连续 `tasks.stallMinutes`（默认 5）分钟读不到新内容"，而且只把"行内容变了"算作新内容（steamcmd 的进度行以 `\r` 结尾，同一个数字能连着重绘好几行）。判停认不出的是另一种：实测到它 `Download failed: http error 0` 之后换一轮包从头重下，行一直在变却永远下不完——那一种由 `tasks.timeoutMinutes` 那道宽上限兜底（本体下载 12 小时、备份与恢复 60 分钟）。两种中断在界面上分开说：判停说"判定这条线已经卡死"并提示去服务器上手跑一次 steamcmd 验链路，跑满上限说这包多大、这一段时间下不完、放宽哪一项。
6. **为什么地图分两条数据路**：地形和建筑/资源要在游戏线程里采样两万个格子，不可能每秒做，所以助手按需导出成 `dstpanel_map.json`，面板只在这一份底图超过十分钟、或者用户点「重新导出」时才排队重导；玩家位置直接从每秒刷新的状态快照里换算成网格坐标（和助手采样用的同一个公式）。两条路合起来的效果是"人在动、底图不用重导"。代价是界面上必须标清楚这份底图是什么时候的。

## 快速开始（开发机）

依赖：Go 1.23；要真正开服还需要 Linux、`screen`、DST 专用服务端（Steam app `343050`）和 SteamCMD（下载模组用）。

```bash
go build -o dstpanel ./cmd/dstpanel
./dstpanel -gen-config cfg.yaml      # 生成带注释的示例配置，权限 0600
# 改 cfg.yaml 里的 kleiRoot / dstInstall / steamCmd / adminPassword（tasks 那两项有保守默认，不用动）
./dstpanel -config cfg.yaml
```

浏览器打开 `http://127.0.0.1:8921`。登录账号是配置里的 `server.adminUser` / `server.adminPassword`；两项没写时用出厂默认账号 `admin` / `admin`。

出厂值故意取最广为人知的那一组：它会出现在 README、教程和部署笔记里，写成口令样子反而等于把它公开。代价是公网端口上一定有人试得出来，所以只要账号的密码还等于出厂值，登录后**总览「下一步」清单里会列一条，顶栏也一直挂着「待办」入口**，改掉了才消失。**部署完第一件事就是登录进去在「账号管理」里改密码。**

默认只监听回环地址；`server.bind` 不是回环、而配置里显式把 `server.adminPassword` 留空时会拒绝启动。

第一次使用（一台什么都没装的新机器也是这条路，各页空状态会直接说下一步去哪）：

1. 顶部如果挂着"这台机器上还没有**服务端本体**"，先去「任务中心」提交下载——建房间不受影响，可以边下边建；
2. 「开服与世界」→ 向导建集群（默认 Master + Caves 双分片），填服务器名、连接密码；
3. 在同一页填 Klei 集群令牌（accounts.klei.com 生成），面板只显示"已配置 + 长度"，不回传明文；
4. 点分片启动，等日志里出现世界加载完成；
5. 需要模组时，在「模组」页按名字检索（或直接填工坊 ID），在卡片上点「订阅并开启」——下载清单和这个房间每个世界的开关一次写完，重启那两个世界才会真的把文件拉下来；
6. 在「存档快照」打一份基线备份；
7. 要给别人权限时，去「账号管理」建号：只看状态就选「只读」，让他管某几间房就选「房间成员」，再在同一页下方那张「房间归属」里点这间房的「指派」——全程不用改配置文件，也不用重启面板。

## 从零部署一台云服务器

面板必须和 DST 服务端跑在同一台机器、同一个用户下（`screen` 和文件权限都依赖这一点）。
一台干净的 Ubuntu/Debian 机器（有 sudo、能连 Steam CDN）从下面第一步开始，全程只需要这三个命令。

### 1. 构建并上传部署包

在开发机上交叉构建。产物是一个静态二进制 + 四个脚本。`deploy/*.sh` 在仓库里存的是 LF
（Git 入库时统一转成 LF，Windows 上 checkout 也不会破坏它），可以直接 scp 上去跑，
不用再手工转换行尾：

```bash
GOOS=linux GOARCH=amd64 go build -trimpath -o dstpanel-linux ./cmd/dstpanel
# 把 dstpanel-linux 与 deploy/{start.sh,install.sh,uninstall.sh,dstpanel.service} 放进同一个目录
scp -r 那个目录 ubuntu@your-host:/home/ubuntu/dstdeploy
```

### 2. 安装

```bash
ssh ubuntu@your-host
cd ~/dstdeploy && sudo ./start.sh install
```

它会依次做完这些事，每一步都在终端上说什么：

1. 校验包内二进制的 sha256（对不上直接停）；
2. 建一个专用运行用户 `dst`，**家目录就是业务根目录 `/data/dst`**；
3. 下载 steamcmd 到 `/data/dst/tools/steamcmd`，并当场跑一次让它更新自己（工具本体实测两百多兆；这一步只是给自己更新，快的时候一两分钟，慢的时候实测过 33 KB/s 跑满 34 分钟。最多等 10 分钟，超了也不拦安装——面板里那条下载任务会再更新一次）；
4. 生成 `/data/dst/panel/cfg.yaml`（权限 0600，里面有 `adminPassword` 的位置），四条路径按 `/data/dst` 展开；
5. 装 systemd 单元 `dstpanel.service`（`User=dst`、`Environment=HOME=/data/dst`、`KillMode=process`），设为开机自启但**不**立即启动；
6. 问一句要不要让面板直接监听公网端口（回车即保持只绑 `127.0.0.1`）。

装完的目录长这样，全部东西都在一个用户手里，删得掉、也看得懂：

```
/data/dst/
├── .klei/DoNotStarveTogether/   存档与集群配置（引擎写死要读运行用户家目录下的这个位置）
├── dedicated_server/            服务端本体（steamcmd 下的 4.28 GB 那一份）
├── tools/steamcmd/              下载工具本体
└── panel/                       dstpanel 二进制、cfg.yaml、dstpanel.db、backups/
```

> 为什么家目录不能随便指：服务端二进制实测**忽略 `-savedir`**，存档一定落在
> `$HOME/.klei/DoNotStarveTogether`；steamcmd 自己的缓存也在 `$HOME`。所以"运行用户的
> 家目录 = 业务根目录"不是审美选择，是硬约束，`install.sh` 会拒绝不一致的组合。

### 3. 启动，然后按界面提示走

```bash
sudo systemctl start dstpanel
```

浏览器打开 `http://服务器IP:8942`（或按安装时那一步的回答），用 `admin` / `admin` 登录，
**第一件事是去「账号管理」改密码**——只要密码还等于出厂值，总览「下一步」清单就会列着它，顶栏也一直挂着「待办」入口，改掉才消失。

登录后界面上会按缺什么就指哪一步：

1. 总览「下一步」第一行提示"这台机器上还没有服务端本体"→ 点「去任务中心下载」提交「下载/更新服务端本体」。在别的页就点顶栏那枚「待办」入口（手机上在「更多」抽屉里）回总览，和房间、令牌一起看。
   这一步是 4.28 GB 的真实下载（实测带宽 10–29 MB/s 时约 5 分钟，慢链路只能等，进度条会一直自己动），
   进度条下面有"已下 / 整包 / 速度 / 还要多久"四个实测数字，
   没有一个是估的（整包大小与速度都从 steamcmd 的输出里读，换台机器数字自己变）。
2. 本体到位后，【开服与世界】向导建集群（默认 Master + Caves），填 Klei 集群令牌（accounts.klei.com 生成）。
3. 【总览】上点那间房的页签，在每个世界那一行点启动。要别人能连进来，防火墙放行的是**游戏端口（UDP）**，不是面板端口：
   面板从 `network.shardPortBase`（默认 10998）往后挑空闲端口，双分片默认落在
   10998（地表）与 11000（洞穴），中间的 10999 是 `cluster.ini` 里的 `master_port`
   ——Klei 的硬规则是它必须等于地表端口加一，所以这三个是一组，放行时要一起放。
4. 需要模组时，在【模组】页按名字检索，卡片上点「订阅并开启」（下载清单 + 这个房间每个世界的开关一次写完），再重启那两个世界让文件从工坊下来；【存档快照】先打一份基线。
5. 要给别人权限，去【账号管理】建号：只看不改选「只读」，要他管几间房选「房间成员」，再在同一页下方那张【房间归属】里点这间房的「指派」——同样不用改配置文件，也不用重启面板。

### 升级与卸载

```bash
# 升级：换上新二进制重跑一次，配置不会被覆盖
sudo ./start.sh install

# 卸载：删单元、删 dst 用户连同 /data/dst 整棵树
sudo ./uninstall.sh --yes
```

卸载脚本最后会全盘扫一遍残余，但**它不替你判断哪些文件是别人的**：命中列表打出来并以退出码 2
结束，逐个确认再删。实测在一台装过又卸掉的机器上，改开部署包目录与异机备份之后重跑同一条
find，命中数为 0。

后半段（建群到两个分片真的在线）也在这台机器上从零走通过：向导建 `Cluster_1`（地表 + 洞穴），
令牌在写盘前就被 `ValidateToken` 验掉格式、落成 0600 的 `cluster_token.txt`（审计里只记位数）；
分片启动后约两分钟助手回第一份快照，`dstpanel_map.json` 跟着落盘。判"令牌真被 Klei 收了"要看

TokenPurpose`；【开服与世界】里"已注册到公网服务器列表"那句是按配置推出来的，不能当证据。
第一次世界生成会打 `PANIC: missing required prefab [...]` 和 `An error occured during world and we
give up!`，引擎随即换种子 `RESTARTING GENERATION` 并成功，那不是启动失败，界面上不用为它报警。
**目前只有面板是开机自启的**，游戏分片仍然要靠【总览】上那一排世界行点启动（它跑在 `screen` 会话里，
故意不进 systemd，见下面的设计取舍）。

### 其他注意事项

- 第一次世界生成时 `server_log.txt` 里出现 `PANIC: missing required prefab [...]` 和
  `An error occured during world and we give up!` **不是启动失败**：引擎紧接着会
  `RESTARTING GENERATION` 换个种子重跑，实测一到两次之内就成功落盘。所以面板不为这几行报警，
  只看进程还在不在、助手有没有回话。
- `kleiRoot` 必须指向运行用户自己的 `~/.klei/DoNotStarveTogether`（同上，引擎忽略 `-savedir`）。
- 服务单元用 `KillMode=process`：`systemctl restart dstpanel` 只重启面板，screen 里的分片继续跑。
- 对外访问的推荐做法仍是 `server.bind: 127.0.0.1` + Nginx/Caddy 反代套 HTTPS，或 SSH 隧道
  `ssh -L 8942:127.0.0.1:8921 you@host`。面板用 HTTP Basic，明文密码裸奔在公网上有风险，
  安装时那句 yes 是明确问过才改的。
- 同一个 `paths.workDir` 只能有一个面板实例：SQLite 与 screen 会话都假设单一管理者。

## 面板设置

「面板设置」改的四项存在 SQLite 里，优先于配置文件，改完立刻生效：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `audit_retention_days` | 90 | 操作记录保留天数；`0` 或负数 = 永久保留 |
| `snapshot_retention_days` | 30 | 在线趋势采样保留天数；`0` 或负数 = 永久保留 |
| `backup_keep` | 配置里的 `backup.keep` | 存档快照最多保留份数；超出删最旧的 |
| `backup_schedule_hours` | 配置里的 `backup.scheduleHours` | 定时备份间隔小时；`0` = 不开 |

保留期清理在面板启动时跑一次，之后每 6 小时一次，所以改小之后旧数据要等下一轮才消失。备份份数与定时间隔这两项的"没改过时用什么"来自配置文件。

## 安全设计

- **密码不走查询串**：认证是 HTTP Basic，凭据只在浏览器标签页的 sessionStorage 与内存里，没有会话 cookie、没有落到磁盘的令牌；对外访问请套 HTTPS。
- **面板账号分级**：账号存在 SQLite 里，密码用 PBKDF2-HMAC-SHA256 加盐散列，库里和日志里都没有明文。「只读」账号能看不能改，写接口一律 401/403；首个管理员账号由配置文件带出来，登录后就能在「账号管理」里改名增删。
- **默认凭据是公开的，所以提醒也一直挂着**：出厂账号是 `admin` / `admin`——故意取最广为人知的一组（它会出现在文档里，写成口令样子等于把它公开），密码长度下限也因此是 5 位：规则比默认值还严的话，照文档部署的人反而会被自己的接口拦住，只能绕过校验写库。面板不拦弱口令，只做两件看得见的事：改密码时短于 8 位当场提示；只要某个账号的密码还等于出厂值，`/api/v1/session` 与账号列表都会标出来，界面在总览「下一步」清单里列一条、顶栏也一直挂着「待办」入口，改掉才消失。别的页不再另铺提醒块。启动日志里同样有一句。
- **令牌永不外泄**：`cluster_token.txt` 走 0600 和原子写，令牌不留 `.bak`；接口只返回"是否已配置 + 长度"；清空令牌会连旧备份一起删。
- **命令不经过 shell**：控制台命令是白名单枚举，服务端拼成单行并直接 `screen -X stuff`；玩家名等自由文本永远进不了 Lua。模组工坊 ID 只接受数字，因为它会被写进 `modoverrides.lua`。
- **配置写入原子化**：先写临时文件、落盘、再 rename，中途崩溃不会留下半截 ini/lua；普通配置覆盖前留 `.bak`。
- **不执行 Lua**：世界设定和模组配置只做数据解析，绝不 `load`/`eval`。
- **前端不拼 HTML**：所有动态文本走 Vue 插值或 `textContent`，没有 `innerHTML`/`v-html`。
- **密钥不进 argv、不进日志、不进响应**：Steam Web API key 只从配置读（配置文件本身 0600），拼接请求走 `url.Values`，不落到命令行；调用失败时上游原文先过一遍 `scrubKey`（把 key 的实际值替换掉）才允许写日志，所以"把整段响应体抄进错误信息"这种写法也不会漏凭据。界面拿到的永远是中文结论，`Error()` 只返回结论，技术原因留在 `Cause` 里。Klei 令牌只在请求体里出现。

`run_acceptance.sh` 里每一步的输出与退出码是分开处理的：输出先进 `.tmp_boot/acceptance/<步骤>.log`，屏上只留尾巴几行，退出码由脚本自己收着并在结尾汇总——有一轮的界面脚本报着两条红、整轮却"成功"，就是因为当时写成 `python xxx.py | tail -4`，管道把退出码换成了 `tail` 的 0。同一排脚本还共用同一套夹具（`.tmp_boot` 那棵树和同一个库），被中途打断的一轮会把夹具留在脏状态、让下一轮报出看着像产品缺陷的假失败，所以 `ui_owner_check.py` 开头会扫掉上一轮留下的临时账号，`ui_dev.py --reseed` 会把被改脏的世界规则逐项写回字典默认值并补齐快照样本。

`ui_shot.py` 存在的原因：内置浏览器在有些机器上没有渲染面（`window.innerWidth` 是 0），布局量不出真假。它直接用 CDP 起一个 headless Chrome（独立 profile、独立端口，清理时只按自己的 profile 路径匹配进程），按指定视口打开页面、登录后截屏，同时把列数、卡片宽度、横向溢出、遮罩尺寸这些值写进 `.tools/tmp/measure_<宽>x<高>.json`。加 `--detail` 展开详情层，加 `--dark` 走深色主题。跑之前先起 `ui_dev.py`——它固定访问 `127.0.0.1:8963`。

`internal/webui` 用 `go:embed` 打包资源，改完 JS/CSS 要重新构建二进制才会生效。

`ui_gallery.py` 存在的原因：开发面板只绑 `127.0.0.1:8963`，人不在同一个局域网就没有任何方式看到界面。它把指定页面按**整页高度**出图（视口高度直接设成 `scrollHeight`，超过 4200px 退回首屏并在报告里写明），再攒成 `.tools/tmp/gallery/index.html`——图片按 100% 宽铺满，手机上不用缩放。这个目录是可直接托管的静态产物，配合任意一条外发通道（Qoder Sites 托管、Tailscale Serve、临时隧道）就是一个能点开的链接。它和 `ui_shots.py` 分工不同：那一支量布局数字，这一支只负责给人看图。

## 已知限制

- 权限做到「角色三档 + 房间归属」这一档为止：管理员 / 房间成员 / 只读，成员按派到的房间划界。一间房只有一个负责人（`cluster_owners` 拿房间目录名当主键），没有副负责人、没有用户组、也不能按页面细分；成员碰不到机器级动作（建房间、面板设置、账号管理、模组库、下载本体），未指派的那些房间他看得见状态但改不动。同一台机器上的多个面板实例（各自独立的 `paths.workDir`）互不通信，跨实例共享归属不在设计内。
- 认证没有失败限速或账号锁定：HTTP Basic 每次都真跑一遍 PBKDF2，暴力尝试的代价在密码本身和端口暴露范围上，公网直开时请务必自己限流或改走反代。
- 面板与服务端必须同机；跨机部署的 `screen` 管理需要另一套传输层。
- 生产服务端只支持 Linux；仓库里的 `screen.exe` 是开发期的替身。
- 集群设置只覆盖 `cluster.ini` 里的玩法项（名称、密码、人数、模式、投票、联机范围等）；分片端口、`master_port`、`cluster_key` 牵动 `server.ini` 和玩家怎么连进来，不提供在线修改，要改只能重建房间。改完要重启对应分片才生效（`cluster.ini` 只在分片启动时读一次）。
- 在线按名字检索模组需要 Steam Web API key；没有 key 时按工坊 ID 安装、上传本地模组仍然可用。封面图只来自工坊接口，磁盘上扫出来的模组没有图，卡片会退回按 ID 哈希取色的色块，不会空着一块。
- 「下载/更新服务端本体」要求所有分片先停（steamcmd 会就地覆盖引擎正在读的文件），面板会拒绝并说清是哪几个在跑。首次下载还要能连上 Steam CDN：实测 steamcmd 那两百多兆的自更新有可能慢到 33 KB/s（跑满 10 分钟还没完），安装脚本的处理是**不拦安装**、把这次更新留给任务中心那条下载任务自己补上；任务侧也不会因为"跑得久"就判失败，只有连续 `tasks.stallMinutes` 读不到新内容才中断，失败原话会区分"卡死"和"跑满硬上限"。
