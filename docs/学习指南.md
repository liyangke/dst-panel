# 学习指南

这份指南不按"文件清单"讲，而是按**读代码时真正会问的问题**组织：一条请求怎么走、每个包在防什么、哪些不变量一旦破了会出什么症状。适合在通读一遍源码时对照着看，也适合之后回来复习。

规模先有个底：Go 非测试代码约 2.93 万行，前端约 1.5 万行（JS 13,216 + CSS 1,929，不含 vendor 里的 Vue 3），660 个 Go 测试函数，接口探针 498 项，13 个页面。项目刻意没有第三方 Web 框架、没有 ORM、没有前端构建工具。这几个数用 `python .tools/size_report.py` 现数，别照抄上一版。

## 1. 十分钟跑起来

```bash
go build -o dstpanel ./cmd/dstpanel
./dstpanel -gen-config cfg.yaml
# 改 cfg.yaml：kleiRoot / dstInstall / steamCmd / adminPassword
./dstpanel -config cfg.yaml
```

开发时更省事：

```bash
python .tools/ui_dev.py     # 127.0.0.1:8963，admin / admin，screen 用替身
```

`ui_dev.py` 会造夹具集群、日志和假快照，并重建 `dstpanel.exe`。注意 `internal/webui` 用 `go:embed`，**改完 JS/CSS 必须重启这个脚本才会生效**——这是我实际踩过的坑，页面看起来"代码改了没反应"十有八九是旧二进制还在跑。

还有一条流程约定（2026-11-09 用户明确要求）：**每次改面板，文档跟着改**。`README.md` 的功能/部署说明、本指南里的界面判据、以及判据因此失效的探针脚本都要一起更新。只改代码不改文档，下一轮回来判据和界面对不上，探针报的红会被当成产品缺陷查半天。

## 2. 一条请求的完整路径

以「点一下启动分片」为例：

1. 前端 `views/overview.js` 调 `act("shard:Cluster_1:Master", "POST", "/api/v1/clusters/Cluster_1/shards/Master/start")`；
2. `internal/api/server.go` 的 mux 命中 `handleShardStart`（`lifecycle.go:67`）；
3. `api/server.go` 的 `authenticate` 先做 HTTP Basic 校验（`server.go:184` 起；默认只绑回环，对外靠反代/SSH 隧道）；
4. 同一个 `authenticate` 里判掉只读账号的写请求（那一档的限制和"哪间房"无关，一句话判完；改自己的密码是唯一例外），成员的限制留给下一层；
5. `guardRooms`（`scope.go`）按"这条请求的主语是哪间房"判成员能不能动——三十多条 `/api/v1/clusters/{name}/...` 做成一个中间件而不是逐个处理器里判，因为漏一条鉴权恰好是最难发现的那类问题：接口自己跑得通、界面也点得动，只有第二个账号登进来才暴露；
6. `shardScope` 把 URL 里的集群/分片名按磁盘上的真实目录校验一遍，脏名字到不了文件层；
7. `procrun.Driver.Start` 拼出 `screen -dmS dst-Cluster_1-Master bash -c '...'`，会话名带集群和分片，一台机器多集群共存全靠它区分；
8. 接口写一条审计（动作 `shard.start`，含成功/失败），返回"启动命令已发出"；
9. 真正的状态变化是异步的：引擎起进程 → 助手 MOD 每秒写 `save/dstpanel_status.json` → `monitor` 每 60 秒采样入库 → 前端 5 秒轮询总览接口。

这里有两个刻意的选择：**启动接口不假装成功**（返回的是"命令已发出"，不是"已运行"），以及**不预先判断令牌**。实测引擎在没有令牌时会打印 "Your Server Will Not Start" 但进程不退出，所以判断交给 `procrun` 对日志指纹的检测（`procrun.go:122` 附近的注释），比面板自己猜可靠。

还有一条不在设计里、是被实测逼出来的：中间件链上有一层 `drainBody`（`server.go`），处理器返回后把请求体剩下的字节抽干。这类接口的房间主语在路径上，处理器压根不读体，于是响应写完了体还留在内核接收队列里；这时关连接，Windows 用 RST 而不是 FIN 收尾，**客户端连已经写好的响应字节一起收不到**——界面上就是点了「启动」而面板报网络错误，审计里其实已经记下了一条 400。本机 127.0.0.1 上 30 次一组的对照：不读体的 POST 重置 14/30（`Connection: close`）和 10/30（keep-alive），由处理器读干净或由这层抽干净的两组都是 0/30，不带体的 POST 和 GET 也是 0/30。为什么放在中间件而不是逐个处理器：三十多条写接口里"要不要读体"本来就不一致，漏一条就是偶发的"看着能用"，而这一层统一做只需要一个上限（4 MB，留给"大上传读到一半被拒"那种不值得挂住请求的）。

## 3. 每个包在防什么

### `internal/dst` — Klei 文件层

- `ini.go`：cluster.ini / server.ini 的读写。Klei 的 ini 没有标准库，自己解析；**字符串值不写引号**（写了引擎会把引号一起当值读，已实测），空值就写 `key = ""` 之外的形态要单独处理。
- `lua.go` + `worldgen.go`：世界设定是 Lua 表，但这里**只解析数据，不执行 Lua**。解析器要容忍引擎回写的两种预设拼法、CRLF，以及"读回来的文件被引擎改写过"这件事。
- `files.go`：`WriteFileAtomic` 先写临时文件、`Sync`、再 rename；普通配置覆盖前留 `.bak`。凭据走 `WriteFileAtomicNoBackup`：轮换令牌的动机常常是旧值泄露了，不能把上一串明文留在 `.bak` 里。
- `cluster.go`：集群创建、令牌、端口。`CreateCluster` 先验参数再落任何一个字节——建到一半失败会留下"有 cluster.ini 没 server.ini"的半成品。

### `internal/procrun` — screen 驱动

用 `screen` 而不是 `exec.Cmd` 直接起的原因只有一个：面板自己要升级重启，游戏服不能跟着断。`screen -dmS` 起会话，停服走 `screen -X stuff "c_shutdown()\n"`，强关才是 `-X quit`。

`Runner` 接口把"到底往 screen 传了什么参数"变成可测的：`procrun_test.go` 里用 `fakeRunner` 记录 argv，钉住会话名、命令单行、超出白名单的输入根本到不了这里。

### `internal/modbridge` — 助手 MOD 的通道

助手 MOD 是面板自带的一个本地模组（`internal/modbridge` 里 embed 的 `modmain.lua` 等）。它每帧/每秒做两件事：

- 把在线玩家、世界状态写进 `save/dstpanel_status.json`；
- 读 `save/dstpanel_queue.txt` 里的命令队列，执行后把 id 写进 `dstpanel_processed.txt`，结果写 `dstpanel_result.json`；
- 收到 `map` 命令时，另外导出一份 `save/dstpanel_map.json`（地形网格 + 建筑/资源/危险点/伙伴随从统计）。

`map` 那份是面板里唯一"文件里装了两万个数"的通道，所以 `map.go` 的 `validate()` 从严：网格边长、世界尺寸、`len(tiles) == grid²`、点位越界、类别不在 1~4、子类编号不认识、非资源点却带了子类，任何一条都直接判整份文件不可用，而不是"能读多少算多少"。宁可让界面走"重导一次"，也不要画出一张缺了东南角的地形图。

协议里地形和点位都用**紧凑数组**：144×144 有两万多格，每格写成 `{"x":..,"y":..,"tile":..}` 光键名就多几百 KB，而 Lua 侧拼字符串本来就慢。读的一方靠下标而不是键名，代价是字段顺序变成协议的一部分，所以 Go 侧用定长数组钉死，Lua 的拼法和 `map.go` 的注释要一起改。

点位这一层现在是**两套格式并存**，这是有意的：

- 新版助手发 `ents`：`[tileX, tileY, 类别, 子类]`，**逐个实体一条，坐标是引擎原始 tile**（425×425 世界就是 0~424），没被 144 网格量化过。要"每丛浆果各画一个图标"，只有这种精度做得到。
- 旧版助手发 `points`：`[格x, 格y, 类别, 数量]` 或带第 5 位子类，一格一条聚合。云机上那份 Lua 要等分片重启才会换，所以面板必须两种都读——`MapData.Aggregated()` 是汇合点：有 `ents` 就按 `floor(tx*grid/width)+1` 现算聚合（**和旧版 Lua 里那一遍同一个公式**，否则换了助手版本同一丛浆果会跳格子），只有 `points` 就原样返回。JSON 数组解进定长 Go 数组时缺的尾部补零值，所以四元组的子类自然落到"没细分"，这条兼容有测试钉着。
- 聚合从"助手做"挪到"面板做"，代价是文件从 122 KB 涨到 170~200 KB（实测这张图 9,487 个实体），换来同一份数据既喂低倍率的计数、也喂高倍率的个体位置。
- 超上限只丢位置、计数照旧累加，所以 `totals` 永远是全量的；两边各有一道容量闸（Lua 12000、Go `mapPointsMax`），改一处必须改两处。
- 类别和子类的**数字编号不出后端**：接口同时下发 `kinds`/`subs` 两张字典（code→key→中文），界面拿键上色、拿中文显示，永远看不到 `2`/`5` 这种协议数字。

**地形编号只能问引擎，不能凭印象**：`api/map.go` 的 `terrainGroupOf` 早前按另一版 GROUND 编号写，而实测 `scripts/constants.lua:686` 里 `OCEAN_START = 201`、`IMPASSABLE = 1`、`ROAD = 2`——于是 201~208 那一整片海（一张 425×425 的森林图里约 1.05 万个格子，占一半）没人认领，全落进"其它地形"，而它的颜色是暗紫红。用户看到的就是一句"正常情况下海会是红色的吗"。这类"我们写的表和消费者读的表对不上"的错，单测和探针都发现不了，因为它们都在跟自己的表比；唯一的解法是把消费者的源码（这里就是云机上解开的 `data/databundles/scripts.zip`）当权威抄一遍，再让测试的期望值直接引用那份编号表。

**同一个坑在状态通道上又踩了一次，而且更隐蔽**：`World` 结构体里曾经放着一个 `Day float64 json:"day"`，助手那边也照着写了一个 `day = st.day`。两边各自"看着对"，而引擎的世界状态上根本没有 `day` 这个字段（把这版服务端 4095 个 lua 全文搜 `state.day`，一处都没有），Lua 取到 nil、JSON 里没这个键、Go 补零值，于是界面上每个房间都写着「第 0 天」，季节昼夜全都对得上，只有天数是假的。Klei 自己也是现算的：`components/worldstate.lua:277` 的 `GetWorldAge()` 返回 `1 + cycles + time`，`prefabs/world.lua:321` 和界面上那个钟 `widgets/uiclock.lua:153` 都用 `cycles + 1`。所以现在的协议只发 `cycles`（已经过完几个整天），天数由 `modbridge.World.DayNumber()` 一处换算，`panel_bridge.lua` 里那一行 `day` 删掉了。为什么放在 Go 一侧而不是让 Lua 直接算：换算规则属于"这份数据怎么解释"，放在读的一侧才能被单测覆盖，而 Lua 那份只有 lupa 那条路能碰。

**助手 MOD 那份 Lua 是面板里唯一 Go 测试碰不到的代码**，它跑在游戏进程里，写错了只会让界面显示"地图导不出来"。所以有 `.tools/mod_lua_test.py`：用 lupa（Python 里的 Lua 运行时）先做语法检查，再用桩替掉 `TheWorld`/`Ents`/`TheNet`，把 `collect_map()` 真跑一遍，断言浆果丛落到"资源·子类5"、切斯特和带 monster tag 的阿比盖尔都落到"伙伴随从"而不是危险、掉落物和特效实体不进图。注意 lupa 是 Lua 5.x 而引擎是 LuaJIT（5.1 语义），这里用到的构造（`ipairs`/`table.sort`/模式匹配）两边一致。

**为什么平铺在 `save/` 而不是 `save/panel/`**：云机实测 `SetPersistentString` 不会创建子目录，`TheSim.MakeDirectory` 在这个构建里是 nil，MOD 自己建不出目录，写子目录会报 "Failed to save file"。

**为什么不用 RCON**：RCON 要额外端口和协议实现，而 MOD 在游戏进程里能直接拿到最准的数据；代价是必须往玩家存档目录里写三个文件。

### `internal/worker` — 异步任务

任务表里的状态机：`queued → running → succeeded | failed | canceled`。worker 一次只跑一条（4G 内存的小机，两个分片已经在吃满，再并发一个 SteamCMD 只会一起卡）。

关键点：

- **payload 由服务端构造**，请求体里没有 payload 字段；用户能影响的只有集群/分片名，入队前按磁盘名单校验。
- 进程被系统杀掉时，任务会停在 `running`；下次启动 `RecoverInterruptedTasks` 把它们标成失败并说明可以重提（`cmd/dstpanel/main.go:154`）。
- 定时备份调度器（`BackupScheduler`）只负责入队，跑的还是同一个 worker，所以定时和手工天然串行，不会两个 tar 同时写盘。

三个任务的前置条件各不相同：

| 任务 | 前置 | 原因 |
| --- | --- | --- |
| 本体更新 | 所有分片停 | `bin64` 正在被使用，更新会换掉运行中的文件 |
| 打快照 | 可以运行中 | 先给在跑的分片发 `c_save()` 并等 2 秒，再打包 |
| 恢复快照 | 目标分片全停 | 运行中的引擎会把内存里的世界再存回去，恢复白做还留下混合状态 |

**进度与判停**（`internal/worker/worker.go` 里的 `progressState`、`moveClock`、`watchStall`，字段结构在 `internal/store/task.go` 的 `TaskDetail`）——这块是这个项目里最值得讲的一段工程，因为它的每个决定都被真实数据打回过一次：

- **进度的唯一来源是 steamcmd 那行 `progress: P (已下 / 整包)`**。字节数往 `tasks.detail` 里存成结构化字段（`doneBytes/totalBytes/bytesPerSec/etaSeconds/phase/downloading`），界面读字段而不是解析句子；`message` 那句人话只给操作记录和失败原因用。**没读到字节 ⇒ `detail` 为 nil ⇒ 界面不摆数字块**，宁缺不假。
- **百分比有两个来源，只能认一个**：steamcmd 自己那列 `progress:` 小数是"这一步状态机走到哪"，括号里的字节才是"这 4.3 GB 下了多少"。开局有一行 `progress: 18.xx (0 / 4594664662)`，跟着小数走就会出现"已下 201.7 MB / 4.3 GB（18%）"这种自相矛盾的话。规则：**知道总量之后只按字节算**，之后绝不退回那个小数。
- **速度是实测的，不是写的**：≥2 秒的采样窗 + EMA，字节倒退就把采样重置（换包/重传会倒退）；500ms 写库节流，避免每个进度行都打一次 SQLite。
- **判停靠"输出还在不在动"**：`moveClock` 只在"这一行和上一行不同"时推进时间戳（steamcmd 的进度行以 `\r` 结尾，同一个数字能连着重绘好几行，重绘不算进展）；看门狗发现连续 `stall` 那么久没动，就取消子 ctx，`ExecRunner` kill 子进程。
- **判停的边界要说清**：它只认"彻底不动"。机器上实测到的另一种坏是 `Download failed: http error 0` 之后换一轮包从头重下（包大小从 35,399 KB 变成 41,370 再变成 41,429 KB，共 4 轮 `Startup - updater`）——行一直在变，判停不会动手，那种情况由 12 小时那道硬上限兜。知道自己量不到什么，比多一个机制重要。
- **三种"没跑完"分开说**：判停 / 跑满硬上限 / 面板自己退出。第三种沿用 `RecoverInterruptedTasks`。文案里的时长一律过 `humanTimeout`（`30 毫秒`、`5 分钟`、`12 小时`），因为 Go 的 `1h0m0s` 直接上界面就是裸英文。
- **两条测试对应两种错法**：`TestStallInterruptsASilentSteamcmd`（真卡死必须杀掉）、`TestStallDoesNotKillAStreamThatKeepsMoving`（每 20ms 推进一行、内容都在变，必须成功——误杀一条正在慢速下载的线，比漏杀一条卡死的线更糟）。

### `internal/backup` — 存档快照

- 归档是 `.tar.gz`，清单单独存 `.manifest.json`：列表页读几百字节 JSON，不用为显示一份快照去解一个百来 MB 的包。
- 每个文件登记 size + SHA256。校验和恢复后复核都复用它，不相信"能解开 = 内容对"。
- 恢复要处理引擎的加载规则：它读 `save/session/<GAMEID>/` 下**编号最大的 slot**，只覆盖 `server.dat` 而留着更新的 slot，进游戏看到的还是旧世界。所以恢复是整棵替换，并保留恢复前的安全备份。
- 打包时跳过 Klei 令牌、MOD 通道文件、引擎日志，每一项都在清单里写原因——快照是可以被下载的。

### `internal/mods` — 模组

- `modinfo.lua` 是**裸赋值**（`name = "..."`），不是 `return {...}`；这是实测踩出来的，早先按 return 表解析，连自家助手都读不懂。
- `mod_dependencies` 的组语义是"组内任一命中即可"，否则静默禁用——面板的一致性检查要把"看起来装了、其实没启用"指出来。
- 工坊 ID 只接受数字，因为它会被写进 `modoverrides.lua`；这是命令注入防线的一部分。
- 在线检索要 Steam Web API key，而这台机器很可能永远没有。所以检索页的设计是**降级不降级界面**：`mods_seen` 表"见过即入库"（扫磁盘、看列表、在线搜到的都往里写），没 key 时按订阅数列出这批已知模组。合并规则是文本非空才覆盖、数字取 MAX、`origin` 里 workshop 压 disk——接口偶尔只回 ID 不回 title，不能把已有的名字抹掉。
- 没 key 时这一页能拿到的只有 `modinfo.lua`，所以 `description`（含 `[[ ]]` 长字符串）和 `tags`（数组和 `{ QoL = true }` 键表两种写法都要接住）也得读出来存进缓存，否则每行只剩一个名字。`serverOnly` 故意不从磁盘这条路填：工坊那边它是 `server_only_mod` 标签，`modinfo.lua` 里没有已核实对应的字段，硬套 `client_only_mod` 会把意思说反。
- 那句中文说明（`explain()`）是接口的一部分，不是前端文案：一条缓存都没有、在线失败退回缓存、只扫到磁盘上的、带"客户端也要订阅"标记——每种降级都要在 Note 里说清原因和下一步，前端只负责显示。
- 缓存表里有一列 `preview_url`，合并时只在"新值非空"才覆盖。原因是封面图只有走在线接口才拿得到，而这一页在没 key 时也要能渲染同一批模组；如果合并规则是"整行覆盖"，一次只回 ID 和标题的检索就会把已经存好的图抹掉，卡片从此永久退化成色块。
- **`POST /api/v1/mods/subscribe-and-open` 是这条动线唯一的写入口**：一次请求写完 `dedicated_server_mods_setup.lua` 的一行，加上这个房间每个世界 `modoverrides.lua` 里的一条 `enabled = true`。为什么要合成一发——分开发的话用户要在三屏之间来回，而"订阅了却没打开"和"打开了却没订阅"这两种半成品状态正是以前工单的来源。为什么不顺手把文件下下来：专用服务端只在启动时按清单拉工坊文件，运行中不会补下，面板去调 steamcmd 单拉一个模组等于造一条引擎不认的路径（见 `internal/mods/mods.go` 顶部那段实测说明）。所以接口回一句人话，界面也照抄这句：**点完以后它是"开着但还没生效"，重启那个世界才真的下来**。
- **关一个模组是"留着条目、写 `enabled = false"`，不是删块**。于是"磁盘上没有这个目录"在这一屏有两种完全不同的来路，徽标必须分开说：清单里还有这一行 → 「文件还没下载」（重启会拉回来，是真承诺）；清单里也没有了 → 「目录不见了」（重启什么都不会发生，那句假承诺不能给）。而且这一句只给**开着**的那一行——关着的那行本来就没在开什么，给它标红等于让用户去找一个不存在的故障。这三条判据全在 `subscribe85_check.py` 里对着接口逐行核，不在代码注释里。
- **残留行的名字靠 `mods_seen` 兜**：取消订阅以后那一行在 `modoverrides.lua` 里只剩 `workshop-数字`，如果界面直接用它当名字，用户看到的是一串编号。缓存里有标题就显示标题（`seenName`），连缓存也没见过（作者把名字写成表达式、面板不执行 Lua 读不出来）才留裸编号——那是无从得知，不是偷懒。

### `internal/steam` — Steam Web API 客户端

这个包只有 499 行（`client.go`，不含那 544 行测试），因为它的表面是刻意收窄的：**只读**（订阅、上传要登录 steamcommunity，面板一个接口都不提供，所以只需要一个只读 key），参数是拼出来的而不是转义出来的（appid、language、返回字段全写死，用户只能决定搜索词和页码，搜索词进 `url.Values` 而不是 URL 路径，也就没有 SSRF 的形态）。

真正值得记的是四份实测契约，都不是文档里写的：

| 现象 | 后果 | 代码里的处理 |
| --- | --- | --- |
| `QueryFiles` 的 response 里**没有 `success` 字段**，只有 `publishedfiledetails` 和 `total` | 按"解 JSON 再看 success"判成败，永远判不出来 | 只看 HTTP 状态码；`statusError` 单独认 403（`ErrBadKey`） |
| 403 的正文是一段 **HTML**，不是 JSON，而且可能很长 | 先读满再解 JSON，报错信息是一屏标签 | 只读固定字节数，正文进 `Cause` 不进界面 |
| 模组挂在**本体 appid 322330** 下，专用服务端是 343050 | 用 343050 去搜，一条都不回，看着像"没搜到" | `WorkshopAppID` 常量 + 注释点名另一个号 |
| `file_size`、`subscriptions`、`time_updated` 这些数字字段**有时是字符串** | 整页按 `int64` 解 → 解析失败 → 上层当成"在线检索没成功"退回缓存 | `flexInt64` 的 `UnmarshalJSON` 两种形态都接 |

最后一条是这次改卡片列表时踩的，也是最坏的一种坏法：**一次成功的检索在界面上显示成降级**。HTTP 200、响应体完整、连图片链接都在里面，只在 Go 侧解码时因为一个写成 `"81234"` 的 `file_size` 炸掉，整页结果被丢弃，用户于是看到"没配 key 才有的那种列表"。所以 `flexInt64` 不是防御性写法，`client_test.go` 里有一条测试专门喂字符串形态的整页 payload——它保证的是"成功不被翻译成失败"，而不是"类型宽容"。同理，解码失败时 `Conclusion` 是一句中文（"Steam 返回的内容不是预期的 JSON……这一页结果没有采信"），因为这条路径一旦出现，界面上必须说的是"结果没采信"，而不是甩一段 `json: cannot unmarshal` 给用户。

还有一条容易忽略：`Details`（按工坊 ID 查详情）对不存在或已被封的条目会回 `result != 1`，**并且没有 title**。不滤掉的话界面就是一排只有 ID 的空卡片，而用户手抄 ID 进来订阅的那条路本来就是为了"我还不知道这是什么"。`usable()` 是这个包唯一的入口过滤。

### `internal/gamelog` — 日志

日志行先判文件类型（server/chat），再按规则表定性成 `(level, event, name, label)`。`name` 是短名（如"存档落盘"），给行前缀和热门筛选；`label` 是整句解释（如"世界落盘存档"），只在选中该事件时展开——每行都挂一句说明会把原文挤出屏幕，而只留短名又说不清规则到底在讲什么。短名默认按事件码从 `eventNames` 取；方括号标签规则（`[Error]` / `[WARNING]`）共用 `plain` 事件码，所以规则项可以自带短名，界面上才能分清"引擎错误"和"引擎警告"。事件目录直接从规则表推出来，保证"筛选下拉里有的，逐行定性也认得"。聊天文件的兜底是把没命中的行当"玩家聊天"，否则日志页的汇总会把它算进"没归类的那些行"，和筛选下拉自相矛盾。

实时推送用 SSE：后端处理日志被引擎清空重写（新一局）时的 `reset` 帧，前端不能自己轮询拼时间线——上一轮的最后一行会被接到这一轮的第一行后面。

玩家事件表（`events.go` + `GET …/shards/{shard}/events`）是"必须两份文件一起看"才成立的那类问题，也是这一层里最难的一层。它回答的不是"这一轮谁干了什么"，而是"刚才那一下是谁干的、从哪连进来的"——管理员排查捣乱玩家要顺着 IP 和 SteamID 去找人，所以每行得把这个人尽量说全。难点在于这些列不在同一行里：IP、SteamID、角色、是否管理员只存在于服务端日志，而进服/离开的公告只在聊天日志里写了一份带标签的形状。所以一次扫描先按会话把人对上（`guid → 账户编号 → 显示名` 三张索引 + `nameUser` 一座桥），行都收齐了才回头补身份——聊天行里那条"名字↔账户编号"可能比它对应的公告行更晚出现，边扫边补会把该接上的线接丢。同一份索引里 `merge` 之所以重要，是因为"哪一行先到"决定同一个人先按 guid 建还是先按名字建，不合并的话他在表里会显示成"有的行有 IP、有的行没有"。对不上就留空：把 IP 安错人头上比那几列空着严重得多，界面那句"认出了 N 个人的连接线索"（`identitySeen`）就是给这个空列准备的解释。`people()` 也不能直接数建过的对象，被 `merge` 并掉的那些还挂在列表里，数了就把一个人的三条线索报成三个人；只连上没走完验证的那条更不算一个人，它接不到名字。

去重只在进服/离开两类上换键（`[去重]` 那一段）：同一个进程往两个文件里打同一下公告，服务端那份是整句 "X has joined the game"，聊天那份是 `[Join Announcement] X`，原文不一样、按原文比对合不掉，一个人进服就被数成两记；而"同一秒 + 同一个人 + 同一种进出"一秒内不可能发生两次。反过来两次一模一样的死亡因为时钟不同，不会互相吃掉。别的成对写法都不能这么合：验证行（`player_auth`）和进服公告（`player_join`）是两个事件码，一次进服在表里就是两行，因为它们各自回答不同的问题——前者说"Klei 认了这个账户"，后者说"世界里出现了一个人"，合成一个就把这一轮的所有证据压成一行。`[Announcement]`（系统公告）压根不在 `behaviourOrder` 里，所以它不参与合并——实测过的两种标签形状各留一条测试夹具，就是为了让"不管走哪条路，进服都只该是一记"这句话有东西可验。踢人记在动手的人名下、被踢的那个进 `target`，否则"谁把他请下线的"这一列答不出来。颜色档位（`warn` / `bad` / `ok`）由这一层作为字段给出、不由前端判，事件码在这里定义，"死亡该显警色还是好转色"换不了地方；中立档靠 `omitempty` 缺键表达，前端判的是"没有这个键"，不是空串。墙上时间只有服务端那份文件给得出（聊天文件里没有 `Current time:` 行），所以那一轮的起始时刻被借去补聊天行的 `at`；不补的话同一张表里就是 `22:59:10` 挨着一个 `[00:01:00]`，而这张表要回答的第一件事正是谁先谁后。同一个锚点也作为 `roundStart` 发给界面，那句「本轮从 … 开始」才有依据；读不到 `Current time:` 时这个键干脆不发，前端也就不会摆出这一句。

筛选和分页必须在后端做：窗口上限是每份文件 2000 行，前端拿到全部再切页等于把两整份日志的解析结果塞进浏览器，而手机上只需要 20 行；更关键的是界面底部那句"第 1~20 条 / 共 312 条"必须是对真的发出去的东西说的，前端自己数只能说"这一页有 20 条"，总数得另外编一个。围绕"屏上的数字自相矛盾"修过两处：一是 `scanned` 说的是"筛了这么多行"而不是"从盘上读了这么多行"——服务端那份为了接身份会多读一大截（`identityLines` 取读取上限，比行为窗口的 500 深得多，因为连接行只在进来那一刻打一次，而几小时后的行为行还得有 IP），把它算进 `scanned` 就会出现头部"每份文件回看 200 行"、底部"从 313 行里定性出来的"，所以多读的那一段既从 `scanned` 里扣掉，也强制把 `older` 置真（`older` 说的是"行为行有没有被窗口切掉"，不是"文件有没有被读完"）。二是「动作」下拉里有"玩家发言"这一档，而默认那道开关把发言整档收掉了——用户点名要发言还按关着算就得到一张空表，而那张空表在说假话（这一轮明明有人说过话），于是 `q.Event == EventChat` 在入口处就当它被显式打开，前端 watcher 同步把开关拨到开、反过来关开关时清掉那一档，保证两个控件打的是一次同一个请求，屏上的状态就是真的状态。页码越界不回空页也不报 400：夹到最后一页并把实际用的页号回写出去，前端照着修自己的状态——"改了筛选只剩 3 页、你却停在第 7 页"报成 400 只会让用户以为筛选出错了。最后，"动作"下拉的选项由 `BehaviourCatalog()` 从 `behaviourOrder` 推出来，一张表两用（筛谁和数谁共用它），这样就不会出现"字典里有它、表格里永远筛不出东西"的假选项——这条现在有探针逐档点过去验（`.tools/ui_events_check.py`），夹具里也因此补了封禁行和一条超过 160 字的长发言，否则那两枚控件在本机永远走不到。

### `internal/monitor` — 趋势

每 60 秒读一次助手状态入库。不按秒存是算过的：跑一个月就是两百多万行，4G 小机的图和库都受不了。保留期清理启动时跑一次，之后每 6 小时一次。

### `internal/store` — SQLite

八张表：`tasks`、`audit_log`、`player_snapshots`、`settings`、`accounts`、`cluster_owners`、`players_seen`、`mods_seen`。连接池固定为 1：SQLite 写锁是全库的，面板写入量又小，单连接把并发写从根上消掉，比调 `busy_timeout` 或引入队列层划算。WAL + 5 秒忙等 + `_txlock=immediate` 在 DSN 里。

### `internal/api` — HTTP 层

只做四件事：鉴权、参数校验、调下层、写审计。错误统一 `{ok, error}`，未注册的 `/api/` 路径回 JSON 404 而不是前端外壳 HTML——否则脚本会把"200 + 一屏 HTML"读成"接口通了、数据为空"。

集群设置（`cluster_settings.go`）是这一层里补丁语义的样本：只改请求里点名的项，密码发空串表示"不改"、清空要单独的 `clearPassword`，改完没变化就不重写文件（否则 `.bak` 会被刷成一份和当前相同的备份），审计只记项名不记值。校验和新建共用一份白名单，但**只查这次改过的项**——文件里本来就有面板不认识的取值时（手工改过），全量校验会让"改个名字"也被挡住。

地图（`map.go`）教的是另一件事：**异步接口怎么把"进行中"说圆**。一次 GET 同时做四步——读状态快照判断助手在不在、读底图文件、判断这份底图够不够新（十分钟内且 `game_id` 对得上）、不够新就排队一条 `map` 命令。排队之后 `pending` 不能只看"文件新不新"：底图可能才导出两分钟（离十分钟的重导门槛还早），但用户点「重新导出」是要看刚盖下去的基地，这时候如果回 `pending:false`，前端轮询第一次就收工，等新图真写回来已经没人再问了。所以判据换成"文件 mtime 是否晚于我们排队的那一刻"（`mapOutstanding`），并且不带 `refresh` 的轮询也认这条；超过三分钟还没结果就把它忘掉，避免界面永远挂着假的"正在导出"。同一批请求的去重靠 8 秒窗口 + 扫一遍队列里是否已有 `map`，两个标签页同时开地图不会让助手跑两遍两万格采样。

账号（`accounts.go` + `store` 里的 `accounts` 表）把原来的单管理员改成三档：`admin`（管理员，管这台机器）、`member`（房间成员，只管派给它的房间）、`viewer`（只读）。密码是 PBKDF2-HMAC-SHA256 加盐散列入库，明文不进日志也不进响应；认证仍然是 HTTP Basic，所以没有会话表、没有 cookie，凭据只留在浏览器标签页的 sessionStorage 里。写接口在鉴权之后再过一道"这个角色动得了这一处吗"（`scope.go`），只读账号和越界的成员撞到的是 403 加一句中文说明。三档角色的**说法**只有一份：`/api/v1/session` 的 `roles` 数组带着"值 + 中文 + 这个角色能做什么"，账号页的两个下拉框和"改角色"都读它——接口拒人那句"角色只能是管理员、房间成员、只读"用的是同一份顺序，前端再抄一份迟早把权限目录说出两种版本。

房间归属（`ownership.go` + `cluster_owners` 表）是这一层里"边界要在哪一侧判"的样本。指派与取消指派共用一条 `PUT /api/v1/clusters/{name}/owner`，请求体只有 `accountId`，发 0 就是取消——两条接口会各自长出不同的校验，而它们的规则本来就是一套。参数用账号 id 而不是用户名：用户名可以改、也允许中文和点，拿它拼路径会多出"改名之后归属跟着丢"这种说不清的状态，而 id 只出现在请求体里，用户看到的始终是名字。几条决定都有具体的失败场景兜着：

- **可见名单在响应里就裁好**（`visibleClusters`），不是"前端拿到全部再藏起来"。成员的房间列表里只有"自己名下的 + 未指派的"，别人的房间根本不在 JSON 里。读归属表失败时筛成只剩没归属的那些——最坏的情况下给出最小权限，而不是"当没这回事全都可见"。
- **「未指派」是看得见改不动**，不是隐藏。房间是磁盘事实，装面板之前就有那几个目录；藏起来等于让他以为这台机器上只有两间房。所以那一档的文案必须同时说清两件事，只读账号那一行的说明也是照这个写的。
- **指派有三道 409**：派给只读账号（它改不动任何东西，派过去只留下一间谁都动不了的房）、派给管理员（管理员本来就管所有房间；真正的副作用是成员的可见集按"我的 + 未指派"筛，一挂到管理员名下这间就从所有成员列表里消失，而管理员看不出自己按了什么）、把成员改成只读时名下还有房间（409 里直接列出房间名，让他知道要撤哪几间）。最后一个管理员不能降级也不能删。
- **归属的说法由后端拼**（`ownerLabel` / `assignedNote` / `ownedByMe` / `ownerAccountId`）：成员打不开账号页，前端拿 id 去账号列表找名字必然找出空字符串，用户会读成"没数据"，而真相是他没权限看。
- **拼出来那句里不放时刻**。后端所有时间字段都是 UTC 的 RFC3339，一旦把 `08:12` 拼进中文句子，界面说的就是服务器时区，而浏览器在 UTC+8——同一份数据两把时钟。所以时刻单列成 `assignedAt`，由前端的 `assignedText()` 用 `dateTime()` 按浏览器所在时区接在那句话后面；`assignedAt` 为空（那一行本来没有毫秒值）就只说那一句人话，不摆 `0001-01-01 08:00` 让人以为数据坏了。Go 单测、接口探针、浏览器实测三处都盯着这两条：句子不含数字时刻、`assignedAt` 必须是 UTC 且落在刚才那一分钟内。
- **任务中心按主语筛**：带房间的任务按可见集筛，认不出房间主语的一律算机器级、对成员不显示。`?cluster=` 那类查询走 `roomVisible`，越界回 403 并说清那间房归谁。成员的 `/api/v1/audit` 更严——按 actor 收成"他自己做过的操作"，把 `actor` 写成别人的名字直接 403。
- **键用房间目录名而不是账号外键级联**：删目录不需要动这张表，顶多留下一行没人认领的归属，列房间时按"磁盘上没这个房间"跳过；反过来删账号要清行，那一步写在 `DeleteAccount` 里，因为界面得先在删除确认里说"这个账号名下还有两间，删完它们会变回未指派"。

出厂默认凭据是 `admin` / `admin`，这一组是**故意**取最广为人知的：它一定会出现在 README 和别人的部署笔记里，写成口令样子只是把同一个秘密多抄几份。既然是公开信息，面板就不假装它安全，而是让它一直可见——`Account` 结构体里没有哈希字段（防止某处忘了脱敏把哈希写进响应），要判断"还在不用默认密码"得走 `store.PasswordHashByID` 这个显式入口，真算一遍 PBKDF2 比对，所以只挂在 `/session` 和账号列表两个低频入口上；界面据此把这条并进总览「下一步」清单（#131 之后不再是两种长相的横幅；同一轮第二轮又把别页页顶那整块提醒下掉，改成顶栏一枚「待办」入口，390px 档收进「更多」抽屉），账号行上挂"默认密码"标签。密码长度下限也因此是 5 而不是 8：规则比默认值还严，照文档部署的人就会被自己的接口拦住，只能绕过校验直接写库——那条路比弱密码危险得多。短于 8 位仍然说得出问题，所以前端在三个密码框上做当场提示，提示的是"会被拒"和"会被猜到"两件不同的事。

玩家管理（`players.go`）最容易讲混，因为它同时碰三套身份，而这三套**互不自动绑定**：在线操作（禁言/踢出/拉黑）走助手 MOD，只对正在回话的分片有效、立即生效；`adminlist.txt` / `whitelist.txt` / `blocklist.txt` 是引擎自己读的纯文本，生效时机三份还不一样（白名单要重启分片，黑名单从面板拉黑则立刻生效），所以每份名单下面各带一句自己的说明；面板账号是登录网页用的，跟游戏里是不是管理员无关。几个细节：动作按 `userid` 而不是玩家名（名字能改，按名字操作会打到别人身上），`userid` 只允许 `[A-Za-z0-9_.-]` 且 ≤64 字符，因为它会被写进名单文件的一行；踢人和拉黑必须在请求体里带 `confirm=true`，服务端再确认一次，不能靠前端弹窗自觉；命令入队后 10 秒内没等到回执回 **202** 而不是 5xx——回 5xx 用户会再点一次，队列里就多一条重复的踢人。写名单前先看有没有真的变化，没变化就不重写文件（否则平白多一份 `.bak`，也看不出"这个 ID 是不是本来就写着"）。

### `internal/webui` — 前端

免构建 Vue 3：字符串模板 + hash 路由（`js/nav.js` 注册页面，`js/router.js` 匹配前缀段）。`go:embed` 把 `assets/` 打进二进制。所有动态文本走 `{{ }}` 或 `textContent`，没有 `innerHTML`/`v-html`。

手机端不是"顺手加个 media query"：390px 下表格换卡片、筛选默认折叠、次要信息用 `order` 下沉、日志正文强制换行、触控目标 ≥36px。`python .tools/ui_audit.py` 会查十二类哑点（每条的判据写在文件头注释里）：模板 class 没样式、生命周期导出没人调用、组件 emits 没人绑定、从 `this` 上解构出来的键根本不存在的、computed 项被写成带参函数、JS 文件过不了 node 的语法检查、import 的名字对侧没导出、模板里当函数调的裸名字不在组件上、组件里调自己的方法漏了 `this.`、写死的图标名图标库里没有、返回值的 computed 被当函数调、`mixins: [X]` 里的 X 本文件既没 import 也没声明。

前三类不报错，只会功能整个是空的；第四类不报错，只会把数值算成 `NaN`；第五到第九类一挂载就抛；第十类只少个图。这一轮补的第十一、十二条各对应一次实测才发现的事故：总览页的 `ShardRow` 写了 `mixins: [RoomAccess]`，却漏了 `import` 那一行（模块求值阶段就炸，连登录页都没了）；账号页把 computed 的 `roleDict` 当方法调了三处 `this.roleDict()`（运行时只报 "is not a function"，页面上却是"这一页一张卡都没有"）。这两种表现都能在截图里伪装成"没数据"，所以只进浏览器脚本不够——`js_error_sweep.py` 兜住当下，静态检查才兜得住下一次写错。

第一条有个例外：导入预览那几块上有 `imp-verdict` / `imp-warn` / `imp-blocked` / `imp-shape` 四枚类名不带任何样式，它们是 `.tools/ui_import_check.py` 点那一枚用的定位钩子（那一片全是 `x-note`，没有钩子就点不准）。豁免判据不是手写名单，而是"这个名字真在 `.tools/*.py` 里出现过"——拼错的那一枚不会出现在任何脚本里，照样报；将来脚本不再用它，它自己会重新变成一条该清的哑类名。

第四条是踩出来的：地图页写了 `const { cw, ch } = this.box`，而 `box` 的键是 `w`/`h`，于是 `cw`/`ch` 是 `undefined`，一次缩放把平移量算成 `NaN`，之后每一帧都画在屏幕外——浏览器控制台干净，只有真的滚一下滚轮才知道。这类写法静态可查，所以进体检脚本而不是进记忆。

归属到了前端只剩三件事要做，但每件都有"多做一处就漏一处"的形状，所以都收成一个共享层：

- **判断只有三条，且全在 `store.js`**：`roomWritable(cluster)` = `me.isAdmin || cluster.ownedByMe`、`readOnlyNote(cluster)`（改不动时那句"为什么"，能改时是空串）、`canAssignOwner()`。房间页上挂着一间房的卡片有五个（世界规则、集群设置、游戏端口、Klei 令牌、远程指令），总览那一排房间卡、账号页那两处（按账号列的"归属"那一列、按房间列的「房间归属」那张卡）还要在同一批字段上摆标记，所以这三条通过混入 `js/access.js` 接到组件的 `this` 上（`writable` / `readOnlyNote` / `canAssign`）。散在这么多组件里写，加第六个卡片必然漏一个，而漏掉那个的表现是"成员点保存，接口回一句中文拒他"——看起来像面板在跟他打太极。「所有房间」那一页原来也是这批消费者之一，2026-11-07 整页下掉了（#129），摆标记的地方从三处变两处，但一条判断都没少。
- **拒因文案只能有一份来源**：任何"这一行为什么没有按钮"的话都从 `readOnlyNote` 出，卡片不许自己编。同理，归属的说法（`ownerLabel` / `assignedNote`）整个是后端拼好的，前端不做中文字符串比较——这条是接口层的规矩延伸下来的，前端一旦写 `if (label === "管理员")`，改一句文案就改了一次权限。唯一由前端加工的是那一句后面的时刻：`assignedText()` 把 `assignedNote` 和 `assignedAt` 拼起来，总览页的归属标签、房间页第一格、指派弹窗三处都改用它，免得三处各写一遍时区换算。
- **藏起来的规则要说出口**。账号页那一行在什么情况下会没有"改成只读"和"删除"两个按钮，有三种理由（当前登录的就是他、最后一个管理员、名下还有房间），而且能叠加——admin 自己就同时命中前两条。最早写成一条 `v-if`/`v-else-if` 链，后面那条永远轮不到，于是那一行看起来只是"少摆了按钮"，看不出是被规则藏起来的。现在是 `rowNote(a)` 把命中的理由拼成一句。同一个页面还有个反向的重复：悬浮标签写 `名下 {{ roomsOf(a).length }} 间`，而它弹出的那句话里后端已经数过一遍，实测出来是"名下 1 间1 间"——标签因此换成不含数字的「哪几间」。

这两个都是只有真拿浏览器点一遍才看得见的问题（前者要拿 admin 那一行看，后者要看鼠标悬浮），所以 `ui_owner_check.py` 里各有断言：一条查"两条理由在同一句里都说全"，一条查 `"1 间1 间" not in 那一格的文本`。

**布局只能在真实渲染里量**。内置浏览器在某些机器上没有渲染面（`innerWidth` 是 0，DOM 读得到、布局全零），所以有了 `.tools/ui_shot.py`：自己拉一个 headless Chrome（独立 profile、独立端口，清理时只按 profile 路径匹配进程，绝不 `taskkill chrome.exe`——用户自己的浏览器正开着），用 CDP 设视口、登录、点「工坊检索」、截图，并把列数/卡片宽度/横向溢出/遮罩尺寸写进 JSON。"手机上会不会溢出""一行几张卡"这类判断没有第二种验法。

模组检索页（`views/mods.js` 的 `Workshop`）就是按这套量出来的，几个决定各有理由：

- **每页 12 张而不是 10 张**。卡片网格的 `size` 要能被列数整除才不留半行孤卡：12 覆盖 2/3/4 列，10 只在 2 列和 5 列下排满。接口上限是 20，12 有余量。
- **封面比例写死 `460 / 215`**。工坊预览图就是这个尺寸，容器照它锁 `aspect-ratio`，`<img>` 就能刚好填满，不需要 `object-fit: cover` 去裁两边——比例对了，卡片高度也才能在图片加载前后保持一致，不然网格会在一瞬间跳一次版。
- **图挂了退化成色块，而不是留白**。`broken[workshopId]` 记下 `@error` 的卡，`hasCover()` 从此不再输出 `<img>`，容器换成按 ID 哈希取色的渐变底（和地图图例、模组列表色块同一套取色）。CDN 在某些网络出口就是不通，这属于常态。
- **描述要洗过**。工坊的 `description` 是 BBCode，真数据里 12 张卡有 8 张带着 `[h3]`、`[url=…]`、`[*]`；`plainDesc()` 一条正则把方括号标签连同 `=` 参数一起去掉再压空白。卡片只放两行，全量文本在详情层。
- **元信息压成一行而不是五个 chip**。`metaLine()` 拼"订阅 N · 大小 · 更新于…"并单行省略；五个小标签在 200px 宽的卡里只会变成一坨彩色马赛克。详情层用 `detailRows()` 摊成键值对，那里才放得下"这条信息从哪来""在这台机器上是什么状态"。
- **详情层必须 `<teleport to="body">`**。这一页的外层 `.card` 有 `container-type: inline-size`，它隐含 `contain: layout`，于是卡片成了后代 `position: fixed` 的包含块——遮罩只盖得住那一张卡，弹窗看起来"卡在卡片里"。这是容器规范里最反直觉的一条。
- **详情层要跟着列表刷新**。翻页或换词之后 `syncDetail()` 按 `workshopId` 回新的 `items` 找同一条，找不到就保留旧快照；不这么做的话，打开详情再翻页，弹窗里的状态还是上一页的。
- **切页签不重取页面数据**。三屏共用挂载时那一次 `GET /api/v1/mods` 的视图，只有组件挂载、或某个动作成功以后 `$emit("reload")` 才会重新取。这条决定了验收脚本的写法：绕过界面直接调接口以后必须整页重进，只点页签拿到的还是旧视图——上一轮就是这么报出一条"取消订阅了还写着文件还没下载"的假红，界面本身没错。
- **窄屏的页签条要把选中那一枚滚进视野**。`.tabs` 在 390 下是横滑的，模组页那一排实测要 494px 才排得下；而 #85 之后"点完订阅并开启"是由代码切到第 3 屏，**没有 click 事件，只有一处 class 变更**，所以 `app.js` 里挂的是 MutationObserver（盯 `class` 属性 + 切页时的 childList 两种记录），命中 `.tabs button.on` 就用两个矩形算位移、只滚这一条容器。绑 click 覆盖不到程序化切换那一次，`scrollIntoView` 会连带把整页往下拽——切个页签结果屏顶那句说明书跑出视野，是另一种读不到。

地图页（`views/map.js`）是前端里唯一画 canvas 的地方，也是最容易在手机上坏掉的一页：

- **地形一次光栅化，缩放靠 `drawImage`**：两万个格子每帧重画必然卡。先把网格写进一张 grid×grid 的离屏 `ImageData`（颜色按 15 组中文地形分组取，Klei 的地形编号不出后端），再关掉 `imageSmoothingEnabled` 放大到画布，像素感正好是想要的；点位和玩家每帧画在上一层，因为它们的数量只有一两千。
- **画布是数据到了才出现的**，所以 pointer 事件不能在 `mounted` 里绑：统一走 `bindCanvas()` / `detach()`，配 `ResizeObserver` 重算 backing store（按 DPR 放大，否则手机上永远是糊的）。
- **宽高比靠内联样式锁**：`aspect-ratio` 撞上 `max-height: 68vh` 时，谁先满足由父容器决定，桌面端会被压成长方形；所以宽度写 `calc(68vh * 比例)` 让它自己收缩。窄屏相反——横屏手机 68vh 会把地图压成一小块，media query 里要把这个上限解除，只靠宽度撑。
- **触屏没有滚轮和 hover**：双指缩放/单指拖动是另写的一套 pointer 逻辑，读数条在触屏上换成手势提示；这个判断写在 computed 里（`matchMedia("(hover: none) and (pointer: coarse)")`），首次求值就缓存，够用了。
- **两份数据来源要分清楚**：底图是按需导出的（可能几分钟前），玩家位置来自每秒的状态快照。所以"玩家为什么在动、地图不用重导"是有意的，界面上必须用一句话说明白，否则用户以为数据坏了。
- **点位分三层出，按缩放二选一而不是叠加**：<2.2 倍资源只画一格一块的深浅晕染（几千个圆点会把地形盖成地毯，青色点还会被读成水塘），2.2~5 倍画聚合形状（方=建筑、圆=资源、三角=危险、菱=伙伴），≥5 倍**整个换成个体图标层**——个体数据本来就包含建筑/危险/伙伴，两套同画只会互相压。图标查表用接口下发的 `kinds`/`subs` 把编号翻成键和中文，界面上不出现协议数字。
- **一格画不下的用 `+N` 兜底**：`perCell = 格面积 / (图标尺寸² × 0.8)`，超出部分不硬叠（12 丛浆果在 31px 的格子里叠 12 个图标就是一坨），在锚点旁边写"树+4"。这条是"密度"和"信息量"之间唯一能守住的位置。
- **筛选只在个体层出现**：低倍率是聚合层，筛掉一类只会把"这格有 12 个"变成"这格有 9 个"，那种数字没人看得懂。筛选项按接口给的字典生成（只列这张图上真有的类别/子类），状态存 localStorage，写失败（隐私模式）就当作没筛过——记不住不该影响看图。
- **图标只借语汇不取素材**：暖黑描边、土色低饱和、顶亮下暗、脚下投影、轮廓故意画歪。Klei 的 `minimap_atlas*.tex` 是它的版权美术，公网面板把素材发给访问者等于分发；要换源就换 `drawEntIcon` 里查的那张表，前端其余部分不动。
- **图例不能画成画布里没有的东西**：玩家点是按角色着色的（和总览/玩家管理页的头像同一套 `nameColor`），图例如果给一个蓝点，就是自己打自己的脸——那里改成按工坊/角色同算法的色环，文字写明"按角色"。同一条规则也管模组列表的色块：按 ID 哈希取色，同一个模组在哪个列表都是同一个颜色。
- **点位按缩放分级出信息**：低倍（<2.2）只把资源画成一格的深浅晕染，几千个圆点会把地形盖成地毯，青色点还会被读成一片水塘；中倍开始画形状（方=建筑、圆=资源、三角=危险、菱=伙伴随从）；高倍（≥5）在旁边写出 `×12`，≥7 才写出子类名（"浆果丛×12"），因为三个汉字加计数约 50px，格子不够宽就互相压字。建筑/危险/伙伴本来就少，低倍也保留形状——把它们也晕成半透明方块，图上会出现一块块说不清是什么的淡斑。

## 4. 值得背下来的不变量

| 不变量 | 位置 | 破了的症状 |
| --- | --- | --- |
| 令牌不进 argv/日志/响应 | `api/bootstrap.go`、`logx` | 凭据泄露，且日志会长期留档 |
| 命令是白名单单行，不经 shell | `dst/console.go`、`procrun` | 玩家名变成 Lua 代码 |
| 写配置先临时文件再 rename | `dst/files.go` | 断电留下半截 ini，世界起不来 |
| 令牌不留 `.bak` | `dst/cluster.go` 的 `SetToken` | 轮换后旧凭据还躺在盘上 |
| 恢复存档必须分片全停 | `worker/backup.go` | 引擎把内存世界回写，恢复白做 |
| 任务 payload 不信请求体 | `api/data.go`、`worker` | 用户能改任务参数，越权动别的房间 |
| 未注册 `/api/` 回 JSON 404 | `api/server.go` | 前端把 HTML 当数据读，错误被吞掉 |
| 玩家动作按 userid，踢/拉黑服务端要 `confirm` | `api/players.go` | 改名后打到别人身上；脚本绕过弹窗直接踢人 |
| 名单只按行增删，不重排不改格式 | `dst/playerlists.go` | 引擎读不出这份文件，玩家进不来而界面显示"已保存" |
| 码值不出后端（地形编号、点位类别、分片代号） | `api/map.go`、`api/lifecycle.go` | 界面出现 `6`、`1/2/3`、`MASTER` 这类没人看得懂的东西 |
| 地形分组表以引擎 `constants.lua` 的 GROUND 为准 | `api/map.go` 的 `terrainGroupOf` | 201~208 一整片海没人认领，一半地图被涂成"其它地形"的暗紫红 |

## 5. 云机上实测踩过的坑

这些是文档里查不到、只能真跑才知道的，面试里也最有说服力：

1. **`-savedir` 不起作用**：服务端二进制（760944）忽略它，永远读写运行用户的 `~/.klei/DoNotStarveTogether`。面板指错目录时一切"成功"，引擎用的是另一个目录里的世界。所以 `kleiRootWarning` 在启动时专门喊一句。
2. **没有令牌时进程不退出**：日志里说不会启动，screen 会话却一直活着。只按"会话存在"判断运行状态会把无效令牌当成开服成功。
3. **`modinfo.lua` 是裸赋值**，不是 return 表；按后者解析，连自家助手 MOD 都读不出来。
4. **`SetPersistentString` 不建目录**：助手 MOD 写 `save/panel/` 会失败，改成 `save/` 平铺。
5. **世界生成 PANIC**：`missing required prefab sculpture_bishop`，来自地形预设和世界字典缺键；补字典、按各自地形写全才过。
6. **`mod_dependencies` 组内任一命中**，不是全命中；依赖不满足时引擎静默禁用模组，界面必须把"装了但没启用"单独标出来。
7. **Steam 那边"看着成功"的三种失败**：403 回的是 HTML 不是 JSON；`QueryFiles` 压根没有 `success` 字段，成败只能看状态码；数字字段（`file_size` 等）有时是字符串。第三条最阴——按 `int64` 整页解码会失败，而失败在上层等于"在线检索没成功"，于是一次成功的检索被显示成降级（详见 `internal/steam`）。
8. **一次下载任务里 steamcmd 有两种带宽，差五百倍**：本体文件下来那一段实测 9.9–29.6 MB/s（4.28 GB、4 分半，`total=4594664662`）；它给自己更新那一段约 115 MB 跑了 34 分钟（不足 60 KB/s，中途 30 秒网卡窗口量到 33 KB/s）。我由第二段外推出"整包一小时内下不完、一定被上限杀掉"，被第一段的数据当场推翻——**同一次任务里的两个阶段不能互相代表**，任何按"典型带宽"写的时长都会在某台机器上误杀。
9. **进度行以 `\r` 结尾，最后一行常常没有换行符**：用 `sed` 原样透传到终端时，下一句中文提示被接在半截尾巴上（实测打印出 `... (19,915 of 41,370 KB)...不影响安装：面板里那条下载任务会再更新一次`）。`deploy/start.sh` 改成 `tail -n 5 "$log" | awk '{print "    " $0}'` 才分行；判停那边"同一行重绘不算新内容"也是为这个语汇写的。
10. **steamcmd 自更新的日志在 `$HOME/Steam/logs/bootstrap_log.txt`**，不在 `linux32/logs/console_log.txt`。找错文件会得出"它什么日志都没留"的错误结论，而那 3359 行 `Downloading update` 恰好是唯一能复盘慢链路证据的地方。
11. **depot 段的状态不止 `downloading`**：实测出现 `0x61 downloading`、`0x11 preallocating`、`0x5 verifying install`、`0x81 verifying update`、`0x101 committing`、`0x3 reconfiguring`、`0x0 unknown`。只认 `downloading` 的话，校验那一段字节量还在涨而界面却停住——所以那一段专门换成"已处理 / 吞吐"，不冒充下载。
12. **仓库里的 `deploy/*.sh` 是 CRLF**：Linux 的 bash 把 `#!/usr/bin/env bash\r` 读成"找不到解释器"，症状很容易被当成脚本逻辑 bug。打包时归一化成 LF，`start.sh` 自己再加一道行尾自检。
13. **开发机上就地更新已装好的 `dedicated_server` 会坏在 `Update state (0x6)`**，而同一份 steamcmd 在云机从零全量下载一切正常——"更新已存在的包"和"从零装"是两条不同的路径，必须分别验，不能拿一次成功当两边都成立。
14. **Git Bash 的命令行里出现中文就 exit 127**（中文文件名、中文 grep 模式、awk 脚本里的中文都算）。所有带中文的远端脚本一律写成文件、`tr -d '\r' | ssh 'bash -s'` 执行，命令文本本身保持 ASCII。
15. **写进代码注释的"实测结论"也要可复核**：`moveClock` 的注释原来断言"卡死的形态就是同一行连着十几行一个字不变"，回头去机器上看那 3359 行——去掉时间戳每行都不同、KB 计数一直在往前，那种形态根本没出现过。真实发生的坏是 `Download failed: http error 0` 之后换一轮包从头重下。这条的直接后果是判停设计里多写了一段"它认不出什么"。

16. **协议里不能放引擎没有的字段**：面板和助手两侧都写了 `day`，而 `TheWorld.state` 上没这个键，Lua 交 nil、Go 补零值，界面上每个房间都是「第 0 天」。这类错单测和接口探针都发现不了——夹具是自己照着结构体编的，两边比的是同一份想象。查清的办法只有两个：去引擎自己的源码里找那个字段（`grep state.day` 零命中），以及看 Klei 的界面怎么算出来的（`uiclock.lua` 用 `cycles + 1`）。修完之后夹具改成只写 `cycles`，天数在 Go 一处换算，Go 单测 / 接口探针 / 浏览器实测三层各钉了一条"不许出现第 0 天"。

17. **"公开的房间列表"里没有"公开的配置"**：#61 那版在公网房间每一行挂一颗「照这间开服」，把那一间的公开字段带进向导当预填，前提是那份快照里有配置可抄。2026-11-04 把 `ap-southeast-1-Steam.json.gz` 逐字段数过（`.tools/tmp/mode_probe.py`、`.tools/tmp/combo_probe.py`；同日两次抽样 10390 / 10286 间，**份数按分钟在变**），能算"配置"的只有 `intent`／`pvp`／`maxconnections` 三栏，也就是向导第 2 步自己一屏就能点到的那三栏。看着像配置的三个字段实测都不是：

    - `mode`：10390 间里 10319 报 `survival`，而其中 6171 间的 `intent` 是 `endless` —— 它是引擎的旧字段，说不了玩法。
    - `season`：取值是 `autumn/spring/winter/summer`，指那一间**现在跑到第几季**，运行态，不是开局设定的季节。
    - `tags` 里 `WS:` 开头那一串：扒到 `mainfunctions.lua:2386` 的 `WORLDSTATETAGS` 才确认是**存档进度位图**（天体宝珠找到没、档案库通电没、裂缝开没开），跟"生成一张什么图"无关。同一行剩下的 tag token 走 `KnownModIndex:GetEnabledModTags()`，只有模组自己声明的标签名、**不带工坊 ID**，反查不可控。

    世界大小、资源密度、Boss、季节长度这些真正想抄的东西引擎压根不上报——它们只在房主自己那台机器的 cluster 目录里。所以 #93 把这个入口下掉（原文与取证在 `.retired/README.md`）。教训有两条：一是**"公开"不等于"有配置"**，凡是要照着外部数据生成的字段，先逐项去引擎源码确认它是不是那件事；二是**写进界面的统计数字必须当场可复核**——第一版文案里"无尽 9346 间 + 生存 5680 间"两项相加已经大过当时标的总间数 11687，是拿一份旧口径凑出来的，重测之后界面只写比例、并标出抽样日期。

18. **替代品要靠自己那一侧的理由**：#93 砍完入口，我当天在向导第 2 步补了一排「常见配置起个头」当替代（#94），用户一句「我感觉这个开服常见配置没什么意义」，拆开是三句实话——第一枚的四个取值和 `WIZARD_DEFAULTS` 逐字段相同，**它一上来就亮着、按下去什么都不变**，而当时的测试还把"第一枚一开始就亮着"写成了通过条件（等于把"这枚没用"钉成绿灯）；另两枚省的是 2~3 下点击，对象就在同一屏下方各一栏一下；依据还是同一份公网众数，也就是我刚用来砍 #61 的那个理由，换成按钮并不会因此变硬，而"16 人拉满"在一台 4G 双分片的机器上方向还是反的。所以这一排同日一起下掉，代码与测试进 `.retired/`，`lobby93_check.py` 只留下"两处拆干净没有 + 默认那四栏 + 手动改三栏对汇总"。**根因不在界面上**：刚删掉一个入口，我不想让收尾看起来是"纯删"，于是补了一排东西——删就是删，补的东西得有自己的理由。

19. **数字的单位全对，采错对象照样差 400 倍**：总览上每个世界写着「这台机器上的占用 内存 2.0 MB · CPU 0%」，看着像单位换算错了，实际是**采错了进程**。面板拿的是 `screen -ls` 报的那个 PID，而 screen 只是包裹进程；引擎是它的子进程（启动命令里 `bash -c "… && exec dontstarve_dedicated_server"` 那个 `exec` 让引擎直接顶替 bash，所以是 screen 的**一层**子进程）。云机上同一时刻两份 `/proc/<pid>/status` 的 VmRSS 是 2024 kB 和 882900 kB——界面上那 2.0 MB 一点没算错，它只是描述了那层空壳。改法是 `sumProcTree`：从根往下按 `/proc/<pid>/task/<pid>/children` 逐层累加 Ticks 与 RssBytes，深度上限 6、pid 去重、读不到的孩子跳过（跳过等于退回修之前的行为，不会更糟）。口径字段名和注释一起改成"一棵进程树的累计量"，`Proc` 那份文档也重写了。钉了三层：Go 单测 `TestSumProcTreeNotJustRoot`（原来那份实现必红）、接口层注释留了那两个实测数字、浏览器实测一条"这一格报的内存 ≥100 MB"。**这条只有 Linux 上量得出来**：Windows 开发机上那一格只回一句短话「内存 — · CPU 采不到」，整句原因在那个标记的悬停里（#130 收掉的：整句摆进 nowrap 的胶囊会把 390 的手机屏撑出 61px 横向滚动），所以脚本把它写成显式跳过的 `·` 行而不是删掉——删掉就等于这条永远没人验。教训是：**"界面数字对不对"要连着"采的是哪个对象"一起问**，只看数值合理不合理（2 MB 看着确实太小了）会一路去查单位。

20. **在已经写了 `order` 的 flex 容器里加子元素，必须跟着排**：房间详情那一块（`.shard-detail`）在 1440 宽一切正常，390 宽却插到「停止 / 收起 / 第几天」上面，把一行切成四截。原因是 ≤560 那段早就用 `order` 把按钮和数据行提前了（`.grow`=1、`.btn`=2、`.row`=3、`.shard-note`=4），而新加的详情块没写 `order`，取默认 0；flex 是先按 `order` 再按 DOM 排，于是它跑到最前面。截图上只看着"顺序有点怪"，量每个孩子的 `getBoundingClientRect().top` 才说得清。补的断言写成"详情块 top 之后不许再有本行的其它可见元素"，钉的是画出来的位置而不是 DOM 顺序（两边都是对的，只有位置会红）。

21. **切完主题立刻量，读到的是上一套主题**：深色那一轮报出的描边颜色和浅色一模一样，截图上是白底白字的一坨——不是产品坏了，是 `.btn` 和 `.room-name` 这轮加了 180ms 的 `color/background` 过渡，脚本点完就量，正好抓在过渡中间。改法是主题翻转后等 1 秒再量再截图，并加了一条 WCAG 对比度断言（房间名字色 vs 它落在的底色，≥4.5）：**对比度比"opacity 是不是 1"更接近用户真正会看见的问题**，前者能抓住"颜色对但读不出"，后者只能抓住"图标没画"。

22. **"没对齐"只有 `getBoundingClientRect()` 说得清，而且断言要会认折行**：用户一句「总览里的各个板块似乎没有对齐」，量出来是四处，全在 CSS 里，DOM 顺序一个字没变——接口探针、Go 单测、甚至"看一眼截图"都发现不了（截图上只像"有点散"）。根因两类：一类是**浏览器默认样式**，`dl` 的 UA `margin: 1em 0` 在这张 12.5px 的表里就是 12.5px，把「这台机器」右侧整列明细表压低，第一行比左边的表盘低一截（实测 333 / 321），详情块里那颗"世界号"和第一行同一毛病（937 / 924）；另一类是**分组标题放错了容器**，「房间」那行标题原来写在左列 `.col` 里，它把左列首卡推下去 43px，而右列那张「在线趋势」不受影响，两列顶边于是差出 43px（567 / 524）——把它挪成 `.grid-wide` 的直接孩子、`grid-column: 1 / -1` 横跨两列，它才真的是"这一区"的标题而不是左列的私有标题。第三处是三枚环：带说明气泡那一枚（存档盘）的名字行天生高 5px，把下面的说明文字整行顶下去（450 / 450 / 455），给它 `min-height: 24px` 统一留位后齐了。窄屏还多一条：**触屏放大命中区那条规则（`.tip-btn` 40×40）会把同一枚的名字行撑到 40 高**，另两枚还是 24，说明文字 590 / 590 / 606。这里不能把 40 缩回 24——那一档（≤900）界面就是给手指用的，点不准比高一点矮一点更烦；改法是让三枚的名字行在这一档统一按 40 留位，并把这条写在 `.tip-btn` 那一条的正下方，两条必须同进同退。

    断言本身也踩了一次坑：第一版四条都直接比顶边，390 宽下三条红——可那两块**本来就该上下排**（≤760 时 `.host-body` 收成单列，详情块那两栏是 `flex-wrap` 折行），红的是脚本不是产品。所以每条顶边比对前要先问"这两块是不是并排"，判据取纵向重叠（`min(bottom) - max(top) > 6`），不并排就打印一行"这一档跳过"、而不是删掉断言——删掉等于窄屏从此没人验。教训：**布局断言要钉的是"画出来的位置"，而"位置该不该相等"取决于当前断点下的排法**；顺带一条反面经验，我先前想用像素扫描（找每一行有没有墨）来定位错位，两次都得出了错结论：详情块自带浅底被当成"有内容"，而后台那一轮验收又把同名截图重写成了深色主题。能量 rect 就别猜像素。

23. **"首页有点空"要先量空在哪，别先想加什么**：用户说首页空，我第一反应是报四个"再加一张卡"的候选（异常待办 / 最近动作 / 事件摘要 / 快照），被他一句"这四个我都不满意"打回。改成先量：1440×900 下文档高 1138、内容最底边 1118、**尾部只空 20px**，双列网格列尾差 0px（上一轮对齐之后就没有斜空白了）——也就是说页面底下根本不空。真正空的是卡片内部：一个在跑、上面还有 2 个人的世界，不点「详情」只剩一行胶囊。把这句话翻译成数字（点一次详情文档高 1138 → 1656，多出来的 518px 全是本来就有、只是被藏起来的内容）之后，方案不是"加一块"而是"把已有的一块摊开"：有人的世界默认显示玩家实况，那五行明细表仍收在「详情」后面。做法是让 `.shard-detail` 同时管两种来路（`v-if="open || live"`），里面每一栏各自决定在不在（`detail-top` 只在 `open` 时渲染），于是"只摊玩家"不用复制一份模板，也就不会出现同一批人排两遍。

24. **两张表的键名都会静默漏人**：详情里那一行原来摆的是 `p.prefab`，界面上就是 `wilson`、`wormwood` 这种码值。换成中文译名时，键名必须用**引擎自己的 prefab**，不是英文艺名——麦斯威尔是 `waxwell` 不是 `maxwell`，女武神是 `wathgrithr` 不是 `wigfrid`；写成后者，这两个角色会永远走"认不得"那支，界面上看不出漏了人，测试也看不出（夹具里正好没有这两个角色）。可玩角色的完整清单不用猜：服务端自带 `data/bigportraits/<prefab>_none`，一个角色一枚，那一档就是引擎认为存在的全部角色。服务端目录里没有 `scripts/` 和语言文件，所以 Klei 官方并没有给中文串，译名只能自己维护，认不得时给一句中性说法（"角色未识别"）而不是回退成码值。钉子是一条正则：那一行里出现四个以上连续小写字母就算漏（`WX-78` 是大写，不误伤）。

    另一张表是三维的排法。上一轮我为了"一眼看出谁快饿死"把血量/饥饿/理智改成三条并排，这轮用户要求回到一行一个——他要的不是"哪种更紧凑"，而是**拿同一种量在人与人之间比**：并排时三条都短，只看得出长短；竖排才能看出"我的饥饿比他少多少"。同一批人多的时候竖排还顺手把高度压住了（紧凑靠行高，不靠并排）。教训：视觉取舍的标准是"用户拿这块屏做什么比较"，不是信息密度；他推翻我上一版时，先按他的用法重排，再把理由写进 CSS 注释，下一轮才不会又被同样的理由改回去。

25. **一张卡拆成两栏，那张卡里所有"按视口折行"的规则就全失效了**：#105 把「这台机器」切成左半（本机资源）+ 右半（未结束的任务）之后，1440 宽下右侧那列明细表被挤成一个字一行——处理器型号竖着排。根因不是新 CSS 写错了，是**一条旧规则不再成立**：`.host-body` 原来是 grid 两列、靠 `@media (max-width: 760px)` 收成单列，而 1440 的**视口**下这张卡自己只有约 680px，媒体查询根本没触发。表盘那一段按内容要 572px（三枚环 × 说明文字各留 176px），剩给明细表的只有 80px。改法是 `.host-body` 改成 `flex-wrap`，两栏各自按**自己这一栏有多宽**决定并排还是上下排（`flex: 0 1 auto` + `flex: 1 1 260px; min-width: 0`），并删掉那条按视口的 `grid-template-columns`。**为什么断言网抓不到它**：那一轮的四条顶边比对全绿——明细表仍在自己那一栏里、顶边也确实比表盘低，"位置对"和"读不出"可以同时成立。所以补了一条守门断言：逐个量 `.host-kv dd` 的宽高，宽 <100px 或高 >70px 就算"这一格放不下话"。另一条路（给容器加 `container-type`）在这里走不通：`contain: layout` 会让容器成为 fixed 后代的包含块，而说明气泡 `.tip-bub` 是按视口坐标摆的。教训：**改布局单位（视口 → 容器）时，要把这个容器内所有媒体查询重读一遍**，并且"顶边齐不齐"之外必须再加一条"每一格放不放得下话"。

26. **断言用像素还是用时刻，取决于要钉的是画面还是数据**：玩家在线时间线那一轮，两条像素判据报红——"同一人身上的两个记号只差 0.5~1.4px"和"第三段压住了前一段"。拿接口原始时刻查（`.tools/tmp/tl_dump.py`，一次性脚本）：24 小时窗、轨道实测 168px 宽，1px ≈ 8.5 分钟，而最短那段的宽度还有一道 0.7% 的下限，所以相差 **233 秒和 1505 秒**的两枚记号在画面上必然挨在一起，三段之间两两间隔 113 秒以上、时间上根本不重叠。也就是说数据是对的，判据错在**拿分辨率去问一个精度不够的问题**。改法是把两条按用途分开：算重没算重只能按时刻判（同类记号相差 <60 秒 才算跨分片重复公告没合掉；同一个人的两段时刻区间相交 才算时长被算两遍），"压字"这种可读性问题才留像素判据（刻度标签的 `right` 不许越过下一个的 `left`）——这一条像素是唯一说得清的。而它一红就真的暴露了产品问题：跨天窗在 168px 轨道上摆 5 个"日期 时:分"必然糊，于是刻度数量与格式改成按实测轨道宽度自适应（`ResizeObserver` 量 `.tl-axis-track`，跨天窗放不下 4 个 74px 位置就退回只显示日期）。教训：**先问这条断言要钉的是"画出来的可读性"还是"数据有没有算重"，再选判据**；用错判据的断言会把正确的实现逼成假红，最后一轮就没人信这些红。顺带一个同类坑：`b.wait()` 传的 JS 必须自己调用（写 `(() => {...})()`，少一对括号 CDP 拿到的是函数、不可序列化，于是恒假），"近 7 天"那两条断言因此在四个档位全部**静默跳过**——静默假绿比假红危险，表达式里要 `!!x &&` 防 null，跳过时打印一行而不是删断言。

27. **验收脚本的前提是数据，不是页面**：同一份脚本在本地夹具（reseed 后有人在世界里）全绿，`CDP_BASE` 指到云机就两条红——一条断"有人的世界自己把玩家实况摊开了"，一条断"时间轴上有刻度"。云机那一轮是真的 0 人、真的没有任何玩家行为记录。这两条不是产品问题，是脚本把自己上一次的抽样当成了世界的常态。改法是判据回到接口：`rows > 0` 却一个人都不认得才报红，否则打印"这一窗这台机器上没有任何玩家行为记录，那组对账跳过"；写的时候注意 Python 的 `if A or check(...)` 仍会执行块体，得写成 `ok = bool(cond) and check(...)` 再 `if ok:`。教训：**能拿到云机上跑的脚本，空态分支要先设计**，否则第一次真机验收的全部失败都是假的，反而把真问题（那一轮确实有的那两条）埋在一堆红里。

28. **兜底排法会静默接管主读法，而断言网对此一无所知**：#113 把 `.host-body` 从"按视口折行的 grid"改成 `flex-wrap`，本意是"放不下就整块落到表盘下面，别挤成一个字一行"。兜底本身是对的，代价是**"环 + 明细表并排"这个主读法从此变成一个没人守的东西**：1440 和 1600 下明细表天天折在环下面，两条相关断言一条按设计打印"这一档折行，跳过"、另一条（每一格放得下话）在折行后反而更宽更绿。用户第二次提的正是同一件事——「处理器型号、网络这几个字段不要放到三个扇形图下面，还是跟原来一样放到右边」。修法分两层：先算宽度账（三枚环按内容 510 = 说明文字 158×3 + 间距 18×2，加 24 的中缝和明细表的 236，左半至少要 770 才并得开），据此把右半那栏任务从 `1fr` 改成定死的 `minmax(256px, 300px)`（它只是"有就列出来、没有就一句话"，不该吃掉一半宽度），并把两栏折成一栏的门槛从卡片 820 提到 1040——**低于这一档宁可让任务整块到下面，也要保住环和明细表并排**。实测 1440：左 818 / 右 300，明细表 284px、最窄一格 210px、最高 44px（型号两行）；云机同一档那串 `Intel Xeon Platinum 8255C CPU @ 2.50GHz · 2 核` 也是两行放得下。教训：**凡是"另一种排法也算对"的断言，都要再问一句主排法谁在钉**；降级、回退、兜底一旦覆盖了主路径，主路径就处于无断言状态，而它恰恰是用户每天看到的那一个。这一条现在钉在 `overview96_check.py` 里：只要 `.host-split` 解析出两档（卡片 >1040、任务栏在右边），明细表就必须与表盘纵向重叠，折行直接报红——只有单档那一侧才允许打印"跳过"。加完还证伪了一次它是不是真能红：一次性脚本注入 `flex-basis:100%` 复刻当年那步塌法，判据立刻从「并排」翻成「不并排」（表的 top 322 → 502）。**一条只在全绿时读过的断言等于没测。**（这一条里的 510 / 158 / 236 / 左 818 右 300 是那一轮的账，#115 把竖线对齐到下方之后全部变了，见第 29 条；#115 那条"竖线"本身在 #116 又被换成了一段留白，见第 30 条。）

29. **"和旁边那块对齐"是一段跨容器的算术，不是把比例照抄一遍**：#115 用户指着一屏说「我希望和下面对齐分割」——「这台机器」卡里那条竖线在 1035 之外 70px，而下方两列的分界就在 1035.3。最直觉的写法是给卡内两栏照抄页面的 `2fr 1fr`，实测**偏左 20px**：`fr` 的分母是"卡内可用宽"，而页面的分母是"整张卡的宽度"，卡片自己那 14×2 内边距被算了两遍。正确的式子只有一行——右档 = `(100% - 28px) / 3`（28 就是卡片左右内边距，100% 是卡内可用宽），竖线于是正落在下方右列的边框上，再把右栏的 `padding-left` 从 20 收到 14，它正文的左缘也和下方那张卡的正文对齐了。真正花时间的不是这条 calc，是它的**代价**：左栏从 818 被压到 748，而上一轮刚把"环 + 明细表并排"钉成硬断言，预算 510 + 24 + 236 = 770 当场放不下（注入这个变体的探针立刻量到折行）。于是把 70px 从环那一段还回去：说明文字 158→142、环间距 18→16、环与明细表的中缝 24→18，明细表反而比原来还宽（272，最窄一格 198px、型号仍两行）；折行门槛跟着重算（458 + 18 + 220 = 696 → 卡片 1040 提到 1060）。顺带一条同批的减法：这一栏卡头那枚「每 5 秒自动刷新」被要求拿掉——多久刷一次是整页的事，写在局部就成了四处重复，下面那行「数据时间 3 秒前」已经把新鲜度说完了。教训：**跨板块对齐的判据只能是把两块的 rect 相减**（"看着差不多"在 1440 就是 70px）；而任何"借宽度"的改动，都要回头把上一轮钉住的那条读法重新量一遍——这次是 #114 那条硬断言替我把第一个变体打红的。

30. **同一页上"分隔"只能有一种手段**：#115 把「这台机器」两栏的分界对齐到下方之后，页面上下两处其实在回答同一个问题（"这里换了一栏"），用的却是两种办法——下面那两栏之间是 14px 列间距 + 右卡 14px 内边距撑出来的一段空白，上面这条是 `border-left` 画的一道线。用户把两处各圈了一笔：「希望像下面那个一样，留一小段空白作为分隔。注意对齐」。删线本身一行就够，真正的活是三件容易漏的事：① **空白带的宽度也要照下面配**，`column-gap` 从 20 收到 14、右栏留 14px 内边距，于是"左栏那一档的右缘 → 右栏正文起点"实测 28px，和页面两列之间（左卡右缘 1021 → 右卡正文 1049）一致（原来那段是 20px 列间距 + 1px 线 + 14px 内边距 ≈ 35px，比下面宽出一截）；② 那 14px 内边距**不能跟着线一起删**——它是"右栏正文对齐下方那张卡正文"的来源，线只是挂在它左边的装饰，一起删掉就等于用一次对齐换一次对齐；③ 改 gap 不会破坏 #115 刚钉的那条对齐，因为左栏是 `1fr`，gap 的增减被它自己吸收，右档的宽度和左缘都不动（反过来，两栏都定宽时 gap 才会挪动分界）。窄档那条 `border-top` 一并换成 18px 空白，否则"上面留白、下面一条线"只是换了个方向再犯一次。教训：**加断言要钉"手段"，不能只钉"位置"**——`.host-live` 的 `border-left` / `border-top` 计算宽度都得是 0 才算数；否则将来有人把线加回来，画面只会显得"更清楚"，没人会觉得不对，而全绿的报告里也不会报警（又是第 28 条那个路子：主读法被兜底静默接管）。（这一条把"分隔只靠留白"钉死了，可用户下一句还是「我看着没有什么变化」——线和留白都是在同一张卡里换手段，层级没动，见第 31 条。）

31. **分隔读不读得出"两块"，取决于层级，不取决于用的是线还是留白**：#116 把线换成 28px 留白之后，用户的原话是「为什么我看着没有什么变化」。根因不在手段：下方那两栏是**两张卡**，各有各的边框和底色，那 14px 是两块盒子之间的缝；上方两半共用**一张卡**，同一片底色里的留白无论多宽都只读成"这里空了一点"。三代方案里 #115（竖线对齐）和 #116（留白对齐）都是在同一层级里换手段，只有 #117 动了层级。改法：这一行直接用页面下方那一档的网格（`class="grid grid-wide host-row"`——同一份列定义、同一个 1080px 断点），两张卡的边界由网格本身给出，于是 #115/#116 那套"列间距 14 + 内边距 14 = 28 像素凑齐"的算术整段作废，对齐不再是量出来的，是构造出来的（1440 实测右卡 1035/1420 对下方右列 1035/1420，缝 14px 对 14px）。跟着有两处必须一起动：① 左卡内宽从 748 变成 741，第 28/29 条钉住的"环 + 明细表并排"预算 696 还够，但笔记本宽度会跌破——而**容器查询不能样式化容器自身**，所以在外面套一层 `.host-wrap` 只当参照物，并用**命名容器**（`container-name: hostrow`），免得影响页面别处的匿名 `@container`；② 新的 `host-row` 也带 `.grid-wide`，所有想取"下方那一档"的选择器必须写成 `.grid-wide:not(.host-row)`，否则第一个命中的就是要验的那块本身，断言自己量自己量得干干净净（假绿）。断言也跟着从"量一栏之内的手段"换成"量两张卡各自的边框、左右缘与那道缝"。教训：**同一页上两处"分隔"读起来不一样，先问它们是不是同一层级的盒子**；在错误的层级上换手段，改三版用户都看不出区别，而每一版的截图单看都"更清爽"。这轮也照第 28 条的规矩证伪过新断言有牙（`.tools/tmp/host117_flip.py`，四个变体注在同一条 `align_rects` 上）：基线六条全绿（右卡 1035~1420 压在下方右列 1035~1420、gap 14 = 14、两轨 `769.328px 384.656px`）；右卡整体右移 40px ⇒ "左缘压在下方右列"红（1075 vs 1035）；去掉右卡边框 ⇒ "有 1px 边框"红；`column-gap` 归零 ⇒ 左缘与缝宽两条一起红（1031 vs 1035、0 vs 14），而"解析出两轨"照样绿——正是第 28 条说的"结构对但画面塌了"那一类，只有像素判据抓得住。（2026-11-09 后注：这一整条连同 #105~#117 的对齐算术都已退场——用户问「顶栏有未结束任务，点击后会直接跳转到任务中心，那右下角的卡片还有必要吗」，右卡整张删掉，`.host-row` 单列、一台机器卡横跨整幅，卡间缝、边框比对、1100px 容器查询都不复存在；判据改成「无 `.host-live` 残件 + 卡宽 = 行宽 + 顶栏入口可点」，见本文件验收清单与 `.tools/overview96_check.py`、`overview105_check.py`。保留这条复盘是因为"层级比手段重要"的教训仍然成立：这次也是直接删掉一个盒子，而不是继续调它的间距。）

32. **验收脚本反复灌数据，也会灌出真数据里不存在的形状**：第 26 条那条"同一个人的两段时刻区间相交才算时长被算两遍"第一次真红是在本机——`ui_dev.py --reseed` 两次之间只隔 83 秒，而它写的日志行时间戳铺在"现在往前 105 分钟"那一段里，于是上一轮（17:32:59 起）的离服行落在 17:34:59，比下一轮启动（17:34:22）还晚。真实引擎不可能这样：每轮启动会截断重写日志，一轮里的行必然落在下一轮启动之前。但库里这种行是合法的（面板只是照行落库），而图上同一个人的轨道里确实出现了两根互相压住的条、那句"一共在线多久"确实加了两遍。修在归并那一层：`mergeOverlapSpans` 把重叠段并成一整段——收尾说法取结束更晚的那一段（那才是这段在场真正的结束方式），只要有一段是被窗口切开的就必须还带着 `ClippedStart`，否则"起点未知"被画成了"确有其事"；隔开两次到场照旧是两根条，并段只动真的重叠。测试 `TestPlayerTimelineMergesOverlappingSpans`。教训：**夹具的不变式要和数据本身一样真**——造数据的脚本违反了一条现实约束时，它暴露的既是测试问题也是产品问题，判据是"真机上这种行可能存在吗"：可能，就改产品；不可能，也要问一句界面遇到脏数据该画成什么样，别只把脚本改小。

33. **一张卡的高度不许由人数决定；而"拉长一块去吃留白"只在拉长之后那块仍有内容时才成立**：#119 的第一问是「玩家在线时长这张卡的长度会受到玩家数量影响，一旦玩家数量多了，就会自动变长」。根因是一人一行、行高写死，24 个人就是 24 行，右列被顶得比左列高一屏。改成摘要条 + 有上限的泳道：摘要条一段一人、恒定 22px；泳道整块只有 168px 预算，行高 =（预算 − 2px 行间距 ×（条数−1））÷ 条数 向下取整，20px 封顶——人再多只让每条变薄，不再变高。（2026-11-05 #122 把这套预算整体上抬了一档：摘要条 22→28px、泳道 168→260px、行高上限 20→30px、行间距 2→4px，并把这张卡挪出右列横跨整幅，见第 39 条；这条钉的规则——**高度是预算除出来的、不是人数堆出来的**——没动。）第一版行高漏算了行间距：12 条 × 12.5px + 11 × 2px = 172px，比预算高出 22px，而 CSS 里那道 `.tl2-lanes { max-height: 168px; overflow: hidden }` 把最后一条**无声裁掉**了。所以块上的 `max-height/overflow` 一起删（现在 `app.css:1479` 那条注释就是留给这个的），预算只留在 JS 一处 `TL_LANES_MAX`（`overview.js` 的 `rowH()` 用它除行高）——**同一件事有两道上限时（那两处就是 JS 的 `TL_LANES_MAX` 和 CSS 给同一个元素的 `max-height`），算错的那一道不会报错，只会少画一条**。合并也定了门槛：只多出一两个人不并（写着「其他 1 人」比不并更难看），多于 12 人才并一条 slate 色的「其他 N 人」，且右边那列时长不给它。
    第二问是右列底下那点空白（1440 剩 32px、2553 剩 84px、1280 剩 216px——左卡自己会按宽度变高，所以这个洞是随宽度漂的）。选了"拉长上面那张「在线情况」"而不是补第三张卡：补卡等于把洞挪进左卡，还要多问一次接口。但**先加 flex、后看截图**，1280 那一档得到的是一块 334px 的空框中间飘着一条平线，比原来那个洞还空。根因在这张趋势小图的纵轴：它原来按"这一窗的最低~最高人数"铺满整个高度，而 `viewBox="0 0 300 100"` 配 `preserveAspectRatio="none"`，高度就是纵向放大倍数——采样全程同一个人数时（本地夹具正是这样；人少又不常上线的房间，一整天都可能是这种数据）拉高只是把那条平线放进更大的空框。于是拉高之前先补真刻度：0 起点、按整人数分档（≤5 一格一人，≤10 两格，≤20 五格，再多十格），顶上一格留给线不让它贴住卡边；横线画在 SVG 里，数字写在 SVG 外面（图内的中文会被横向拉扁）。填充也恢复成全程都画——轴有 0 起点之后那块色就是"这段时间坐了多少人"的面积，线平时它说的正是"这么多人数一直没变过"。
    钉法分三层：`players125_check.py` 在 Python 侧按同一条规则（`lanes_rule`）独立复算条数与行高再和界面上比（#125 起这份镜像跟着卡搬到玩家管理页那一轮，前端算错半个像素就红）；一次性探针 `spark119_probe.py` 在 fetch 那一层换掉 `/api/v1/stats` 的响应，用起伏 0~6 / 全程 3 / 全程 0 / 十二人房 / 只有一个点五组造数据，逐档量"刻度数字互不压字、每条横线正对着它那一枚数字（<2px）、线不许画出场、点不够时走那句空态"；留白由 `gap119_measure.py` 在 1280/1440/1600/2553 四档各量一次左卡底 vs 右列底。教训：**"这块空"要先量出它随什么漂**（这里随视口宽度，不随人数），再决定让谁吃它；而"有内容的高度"是要证的，不是默认成立的。这一轮也照旧被自己的工具绊了一次：`b.js()` 传的是表达式，写 `() => {...}` 少一对括号会拿到一个不可序列化的函数、恒返回 `{}`，那条探针因此差点什么都没量到。
    （2026-11-05 #123 更正：**这一套"拉长上面那张卡去吃留白"的前提已经没了**——#122 把泳道卡挪出右列之后那一列只剩这一张图，富余全灌进图场，2226 实测图场从 118 被拉到 536，改法见第 40 条。原文留着是因为它那条"拉高之前先补 0 起点真刻度"仍然成立，而且它正是第 40 条里"图场定值之后这张图还读不读得出东西"的依据；要记住的是**这条规则从来不是"留白该由谁吃"的答案，它只是当时那一列有两张卡时的答案**。）

34. **"这一页少了几条"和"这一页整块没了"必须是两条判据**：#119 那一轮 `ui_filters_check.py` 报了 90 条同源红——"10909 条分 219 页"那一段从第 130 页起每页都是 `0 条（应 50）`，两枚翻页按钮还都读成 `None`，最后一句 `浏览器已经不在 #audit，停在 #(空)` 才把线索露出来。我先怀疑的是界面翻页，而根因在**我自己的动作**：`.tmp_bin/dstpanel.exe` 的 mtime 和面板进程的 StartTime 都是 05:01:53，那一轮却跑到 05:24 才结束——为了另一组探针，我在脚本跑到中途时重启了面板。接口从那一刻起连不上，`api.request` 走 catch 回 `ok:false`，`audit.js` 的 `load()` 于是 `rows=[]`、`more=false`，而 `.pager` 写的是 `v-if="rows.length"`，整块不渲染。也就是说"面板没了"在 DOM 上的长相和"这一页真的没数据"一模一样。修的是判据而不是产品：循环里每页先问一次"表 0 条 **且** 两枚按钮都不在 DOM"，命中就立刻停，并把错误框那句、`location.href`、正文长度一起报出来——正文只剩十几个字是标签页崩了，还有一堆字是这一页被换成了别的页。顺带把这一段从"每页睡死 1.2 秒"（221 页 ≈ 4.4 分钟，而且接口慢一点就读到上一页）改成等页码那一句真的变成「第 N 页」（`.pager .muted`）：同一件事的判据从"睡够"换成"看到证据"。改完 221 页 / 11033 条全绿。教训：**同源噪音不只是吵，它会把唯一的线索留到最后一句**；凡是"读不到东西"的判据，都要先分清是"少"还是"没"。

36. **量"按需展开的那句说明"要用真鼠标事件；而"展得开"和"写清了"必须是两条判据**：把这一版换装到云机之后 `overview96_check.py` 报 8 条红（四条 × 两个视口），条条都写着"读回空串"却没有一个字说明为什么空。一次性探针 `hint96_probe.py` 把四种状态各量一次，结论是：`btn.focus()` 之后 `document.activeElement` 确实已经是那枚按钮，可组件的 `@focus="show"` 没被触发——headless Chrome 在**文档本身还没拿到焦点**时只改 activeElement、不发 focus 事件；同一个页面上第二次再 focus 又开得了（因为第一次之间发过真鼠标事件，页面被激活了），而把鼠标移到按钮上（`Input.dispatchMouseEvent` 的 `mouseMoved`）每次都立刻开。本地夹具两种都开，所以这条红在本地永远看不见——只有指到公网那份成品才露出来。修的是探针：`cdp.py` 加了一个 `hover(b, x, y)`，`open_hint()` 改成先悬停、十二次都没开才退到 `btn.click()`（那是触屏用户的正路），两条都不开就返回空串。**并在这之前先钉一条"那颗说明展得开（读回的是气泡原文，不是空串）"**：少了它，气泡没出来会伪装成四条"文案写得不对"，读报告的人跑去改文案，而真要修的是展开那条链路——判据里"读不到"和"读到了但不对"必须是两种红。有牙也是证的：`hint_open_flip119.py` 三档——A 正常读到 97 字、B 掐掉悬停（`pointer-events:none`）仍读得到（说明备用那条点击路活着，这是证据不是红）、C 把按钮整个摘掉必须读回 0 字、D 恢复后又要读得到。

38. **"命令已投递"不等于"动作已完成"，而记录里的状态句要带判据**：这一轮是纯操作轮（清回滚件、把内嵌的新助手 Lua 落盘、重启两个世界），三处坑都长在接口与记录上，不在产品里。
    第一处最贵：我为了控制两个世界的先后顺序，自己拼了 `stop` → `start`，而 `POST .../stop` 只是把关闭命令注入 screen 会话就返回，响应里那一刻**还是 `running=true`**（存档正在落盘）；紧接着的 `start` 因此拿到「世界已在运行」，而世界是在那之后才真退出的——结果地表停着谁都没管，直到单独补一次 start 才起回来。面板自带的 `POST .../restart` 内部有 `waitStopped`（等到会话真没了再起，等不到就报"多半是存档正在落盘"），**跨版本重启世界就该用它**；真要自己拼，等的证据必须是"那个 screen 会话不见了"，不是"接口回了 200"。
    第二处：探针里那个打印分片状态的函数一路输出 `None/Caves 在跑=None pid=None`，看着像接口坏了。实际是 `GET .../shards/{S}/status` 的响应里**根本没有 `cluster` / `running` / `pid` 这三个键**（它是世界实时快照：shard / day / cycles / season / online / players / updatedAt），在跑与否要问 `/api/v1/rooms` 或直接数 screen 会话。读错的键不会报错，只会静默变成 `None`，所以脚本里凡是"用 `.get()` 兜底打印"的地方，量出来一片 None 就该怀疑键名而不是怀疑服务。
    第三处最该记住：我连着两天在记录里抄"两个世界从 11-02 起没重启过、所以助手新 Lua 没生效、工坊文件一个都没下来"。实测**世界 11-03 21:08 / 21:24 各重启过一次**，Global Positions 也在那一次就落到了 `ugc_mods/<cluster>/<shard>/content/322330/378160973`——"一个都没下来"是因为去 `dedicated_server/mods/` 找 workshop- 目录（引擎日志里 `../mods/workshop-378160973/...` 那个 `../mods/` 是显示用路径，不是真落点）。三条判据现在钉死了：`game_id` **不随重启变**（不能当证据），能当证据的只有状态文件里 `seq` / `heartbeat` 归零重启数（实测 141196 → 4）和引擎进程的 `lstart`；助手 Lua 到没到引擎看 `GET .../helper` 的 `differs`；日志文件名是 `server_log.txt`。教训：**记录里任何"还没做 / 还没生效"的句子都要附一条能当场复验的判据**，否则下一轮只会把它当事实抄下去，而且抄得越来越像真的。

39. **"看不清"一张 24 小时的时间线，先量它每一像素代表几分钟，别先去调字号**：#122 用户在 2226 宽那一档圈住「玩家在线时间」说「这一块是不是有点太小了，我都有点看不清了」。直觉是把字号、行高往上调，而真正的瓶颈是**宽度**：这张卡当时住在右列里，右列轨道只有 430px，一行里还要先给姓名 110px、给累计时长若干，剩下的才是 24 小时的轨道；一窗里上百段进出摊到那 300 出头像素上，**1px ≈ 3 分钟**，间隔四分钟的"离场 → 上线"在图上本来就贴成一坨——字号再大也只是把一坨更清楚地糊在那里。所以改法是把这张卡从 `aside.col` 里挪出来，变成 `.grid-wide` 的直接孩子并用 `.grid-wide > .tl-wide { grid-column: 1 / -1; }` 横跨两列（2226 实测轨道 430 → **1806px**，1440 拿到 1020px，1080 拿到 660px；390 手机那一档轴原来是 248px、泳道 181px，第三问把时长那一列删掉之后两枚都是 256px）。
    宽度一动，高度预算必须跟着抬，否则换来的分辨率被行挤回去：摘要条 22→28px、泳道整块 168→260px、行高上限 20→30px、行间距 2→4px，行内记号点删掉那条 5px 的局部覆盖、回到 `.tl-mark` 的 7px（这是第 30 条的反面用法——不是"再加一道手段"，而是"把当初为窄轨道压小的那一级还回去"），姓名 12.5px。
    同一天他补的第二问才是真 bug，而且是**我自己验不出来、他用眼睛找到的**那条（这一句要说老实：那一轮静态审计和五档对账都是全绿的，而 `ui_audit.py` 查的是"类名有没有定义、码值有没有上屏"这类可静态判定的事，它压根不管"两枚刻度写的字一样"——图形语义的缺陷只有读图的人会撞上）：轴上原来量到 `13:06 / 19:06 / 01:06 / 07:06 / 13:06`——首末两枚同字，读者不知道最后那枚是今天还是明天。判据写错了地方：组件里那句是 `crossDay = w.span > 48 * 3600 * 1000`，也就是"窗口超过 48 小时才算跨天"，可 24 小时这一窗照样跨过零点，而且首末两枚天生相差整 24 小时。改法是把判据换成"这一窗会不会有两枚落在同一个钟点上"（`span >= 21h` 就会），凡是**日历日和前一枚不同**（含第一枚）的那一枚就带上日期，其余只写钟点；带日期那一枚按 74px 给预算（实测 71px、11px 字号），而且首尾两枚是贴边对齐的、要先扣掉半枚宽再数能放几枚——不扣的那一版在手机那一档算出 4 枚、第 2 枚压住第 1 枚 4px；于是窄轨（手机 256px）自动从 5 枚退到 3 枚而不是把 5 枚挤糊。原来那套 `withClock = trackW >= 4 * 80` 的两档写法一并删了——它同时管"枚数"和"要不要写钟点"，跨天窄档会退回"只有日期、读不出几点"，而这一窗真正要认的是"哪天几点"。教训连着第 26 条：**"不压字"和"排得开"是几何判据，"每枚都在说不同的事"是语义判据，两者不能互相代替**；现在 `.tools/overview105_check.py` 里对应钉了四条——枚数按 `ticks_rule(实测轨道宽, 窗口秒数)` 独立复算再比、每枚都读得出钟点、**刻度文字一枚都不重样**、跨零点那一枚（和第一枚）必须带日期（一次性变体 `tick122_flip.py` 证过牙：把首末改成同一个钟点必须红 1 条、把日期全摘掉红 2 条、多塞一枚红 3 条；横跨整幅那两条另有 `tl122_flip.py`，把卡塞回右列必红）。

42. **"这一季第几天"只能问引擎，不能自己算：季节长度在 Klei 那里是分模式拼的**：#128 用户说「当前虽然能看到是第多少天，但是看不到现在是四季中的第几天」。第一条路是拿世界天数去除季节长度（20 天一轮），这条路当场否掉，因为去服务端 `scripts/components/seasons.lua` 里看了三处：春、秋的 `_totaldaysinseason` 被人为乘了 2（`remaining` 却从真实长度起算）、`MODES.always` 把 total 报成 2、无尽模式更直接——对外那句"还剩几天"写的是哨兵值 `ENDLESS_DAYS = 10000`。任何自己拼的除法都会在这三种世界上分别错出三种样子，而且错了也不报错。

    真实在维护这两个数的是 `components/seasons.lua`（换季时"过完几天"归 0，每天 +1），它把 `elapseddaysinseason` / `remainingdaysinseason` 随 `seasontick` 事件复制进世界状态（`components/worldstate.lua:122-123`），洞穴那份由 `shard_seasons.lua` 走同一套。所以助手只是把这两个读数原样抄进快照（`panel_bridge.lua` 的 `collect_status`），换算只有一处、只有 `+1`，与第 16 条那个「第 0 天」修完之后定下的口径同一个形状：**协议里只放引擎真有的字段，一切需要判断的话都在 Go 一处说**。

    "有没有得说"这件事必须留在后端，因为它有三种没得说：老版助手没报这两个键、无尽模式（哨兵值）、固定季节的世界（过完的天数一路涨过任何真实季节长度）。判据收在 `internal/modbridge/status.go` 的 `DayInSeason()` / `DaysLeftInSeason()`，返回值的第二个布尔决定接口给不给这个键，DTO 用 `*float64` + `omitempty`——**键整个不出现**，界面就一个字都不补；要是给个 0，界面上就会出现「秋天（第 1 天）」这种看着像真事的假数，正是第 16 条那个 bug 的换皮。

    写法上有一处是为了不让人误读：胶囊写成「秋天（第 6 天）」而不是「秋天 · 第 6 天」，因为它左边那枚就是「第 21 天」（世界年龄），两个"第几天"用同一种语气并排摆着，读的人必然以为其中一个是编的。还剩几天不进正文、只进那枚胶囊的悬停（第 41 条那条分层：卡内的解释按需展开）。

    三层各钉一条，缺一条都会漏：Go 单测 `TestSeasonDayCounting` 五种情况（常规 / 开局 0 天 / 键缺失 / 哨兵值 / 涨过了头）；`api_probe` 从 HTTP 那头正反各钉一条——有读数时报 6/14，没读数时**两个键都不许出现**；`day92_check` 在人眼那头读总览那枚胶囊的文本与 `title`。夹具改成过完 5 天、还剩 14 天（6 + 14 = 20，正好一个秋天，第 6 天本身不在"还剩"里），这样界面画出来的三个数彼此能对上账。

43. **"没有横向溢出"不能拿 `window.innerWidth` 当视口宽度**：#129 把「所有房间」那一页下掉之后，`ui_connect.py` 里那条早就指错选择器的断言第一次真的跑到了 390 那一屏，量出 `docSW=451 / winW=451`——判据 `docW <= winW + 1` 绿灯，可手机上其实多了 61px 的横向滚动。原因是 390 这一档走的是 `Emulation.setDeviceMetricsOverride{mobile: true}`：内容装不下时 Chrome **把布局视口自己放大**去迁就内容，于是 `innerWidth` 跟着 `scrollWidth` 一起变，两个数永远相等，这条断言从写下那天起就是永真式。撑出那 451 的是世界行上那枚「占用」胶囊——`procText` 把接口整句「这个系统上采不到单个进程的占用（面板跑在 Linux 上时才有）」接进了一个 `white-space: nowrap` 的标记里（Windows 上 `cpuReady` 恒假才走到这一支，云机上碰不到，所以一直没人看见）。两件事一起改：那一格只留短词「CPU 采不到 / CPU 还在测」，整句挪回它的悬停（和 `app.css` 里公网标签那一排同一个分层——长的截掉、全文留给悬停，而不是把省略号当正文）；`js_error_sweep.py` 与 `ui_connect.py` 的溢出判据改成跟**要求的那一档宽度**比。**教训是判据里的"基准"必须是独立于被测内容的第三个数**：拿被测页面自己报出来的宽度判它自己溢不溢出，页面再怎么撑都会说自己没溢出——和第 24 条"夹具是自己照着结构体编的"是同一类错，只不过这次编的是尺子。

44. **一条断言能不能点到那个元素，取决于上一段顺手给它留了什么状态**：整轮验收里唯一那条红就是这个形状——`ui_filters_check.py` 在 1440 报「`.audit-on button.linkish` 里的『全部清掉』找不到（no-el）」，同一份代码在 390 全绿。先别怀疑选择器：一次性探针在两档宽度各 dump 一次 `outerHTML`，按钮两边都在，DOM 没坏。真因是这条断言点的是**第二次**清掉，而第一次清掉（翻页之前那一下，故意的：挂着筛选测翻页会把筛选的功劳算成翻页的）已经把四条轴撤空，`.audit-on` 整行随 `v-if` 消失；之所以 390 侥幸能点，是因为翻页循环里那句「换时间档要回第一页」会把筛选重新挂回去，而那句包在 `if pages > 1` 里——1440 那一刻审计表只有 36 条、只有一页，条件不成立，于是同一个探针在两份数据量下结论相反。**"另一种数据量下也算对"的断言等于没测**（第 28 条的老账，这次红在"点得到"这一侧而不是"量得到"这一侧）。改法是把前提收进这条断言自己：先主动挂一枚最小条件（时间档），钉一条「清掉之前确实挂着条件」，再点「全部清掉」验它回到 0 枚——这样它和审计表有几页彻底无关。诊断动作也值得记一笔：`no-el` 先问"这个元素存在的前提是谁制造的"，再去想选择器过期；宽窄两档结论不一致时，差异多半在某个 `if` 上，而不是渲染上。

45. **"两处都叫待办，数字却不一样"是状态放在组件里造成的，不是文案没对齐**：#134 用户「我还是希望能显示数字，他的口径和卡片栏里的待办一致即可」。原先顶栏 `shell.js` 的 `pendingCount` 只数 `pendingRows(state)`（`/session` 给的默认密码、缺服务端本体两条），总览卡头的「N 项待办」是 `overview.js` 里另一个 computed，还多出房间 / 令牌 / 助手 / 备份四条——两个数组都叫"待办"，一个数 2 一个数 3，看着像算错了。上一轮的处置是"顶栏干脆不写数字"，这一轮用户把数字要回来，就不能再靠删显示回避：**把清单计算抽成 `js/pending.js` 的 `checklistRows(state, rooms)`，把 `/api/v1/rooms` 的快照抽成 `store.state.checklist` + 全局 `loadChecklist`**，顶栏与卡片都读同一个函数的返回值，两个数字从构造上不可能分叉。
    取数也从"挂在总览页的 watcher"改成全局：登录拿到 `state.me` 时取一次、`refreshAll` 每四次轮询取一次（约 20 秒，因为 `/rooms` 是全盘扫描），`loading` 去重挡住两处首次触发撞车，`seq` 挡住「重新核对」连点时的晚到回包；只读账号不扫盘，清单里只剩 `/session` 那两条，两处数字照样一致。教训是**同名的两处计数必须共享同一份数据源，而不是各自算完再约定口径**。CSS `order` 那笔账也一起还了：DOM 顺序改成「下一步 → 房间 → 这台机器」，与视觉、Tab、读屏三者一致；顶栏入口的 `scrollIntoView` 从 `center` 换成 `nearest`（卡已在页顶，别再把首屏往下推）。
    同一轮还有三条值得钉的判据。**一、有待办才摊开整张卡**：清单为空时 `.is-quiet` 收掉卡头，只留一行「都齐了」，正常状态不白占首屏——"下一步在页顶"和"状态优先"不冲突，靠的是条件化而不是硬搬。**二、一间房 6 个角色不会把房间卡撑塌**：`.grid-cards` 的 320px 下限在 768 那一档只能排一列，六张玩家卡竖着叠六百多像素、右列两张图却只有三百；`.detail-players` 收到 `minmax(200px, 1fr)` 后 1440 / 768 实测都是 3 列 × 2 行（网格 344 / 381px），`.shard-detail` 再封顶 420px 内部滚动，人多也只在这一格里滚，390 单列由同一个上限兜住（**这一条在第五轮被按人数分档取代，见第 46 条**：两层都只是把人藏起来，不是让人排得下）。**三、次要按钮在两套主题下都得认得出**：用户嫌深色主题下按钮是"黑色实心块、有点粗糙"，改半透明浅底 + 主文本色之后，1440 浅色截图里几枚按钮又淡得几乎看不见——浅色主题必须另给一层实心 `--card-2` 浅灰底和稍深的边。**"去掉黑砖"不等于"把按钮去掉"**，深浅两套主题都要出图看一眼。这些判据都收在 `.tmp_boot/check134.py`（六档 × 深浅）。

46. **形态由状态算出来之后，"克隆 DOM 造数据"的探针会静默地一直验旧分支**：#135 用户接着上一轮问「既然多个角色会乱，你打算怎么解决」，回「按你说的做」。先把第四轮那两层改法的边界说清：`minmax(200px,1fr)` 让 6 人在 1440/768 排成 3×2，可 390 上内容 1075px、可视 418px，只看得到两张多；`max-height:420px` 也不是让人排得下，是把后半截人藏进一个只有这一格会滚的区域（右列静止，读起来像页面破了一块）。根子是**富信息卡的信息密度固定、人数却不定长**——压窄卡片、封顶滚动都是让固定形态硬适配可变队伍。改法是反过来让形态跟着人数走：`overview.js` 的 `playerMode` 分 ≤4 富卡 / 5–8 紧凑行 / >8 摘要+展开三档，单条 36px，人越多每人占的高度越省，任何人数都不会把房间卡撑爆。三条三围从竖排长条换成同一行里三段等宽细条，**位置逐行对齐**才保住"在人与人之间比同一条"这个能力；坐标、物品数、精确值退到整行悬停。`null` 三围画淡底全宽 + 悬停「未知」，绝不画 0%。
    真正踩到坑的是验收。第四轮 `.tmp_boot/check134.py` 用 `cloneNode` 把第一张玩家卡复制到 6 张来量列数——那时形态只由 CSS 定，能验；这一轮形态是 Vue 按 `players.length` 算的，**克隆出来的节点不进 `state.statuses`，`playerMode` 根本不会重算**，脚本还会"全绿"，只是验的是一张永远不存在的 6 卡网格。所以新探针 `.tools/player_modes_check.py` 改走真实链路：改写本地界面服务器那份 `dstpanel_status.json` 的 `players` / `player_count` / `seq` / `heartbeat` → 后端每次 `/status` 都 `os.ReadFile`（`modbridge/status.go`，没有序号缓存）→ `store.loadStatus` → Vue 重渲染；点数「立即同步」，等人数真的到 DOM 上再读形态。两个副产品值得记：**改的是所有验收脚本共用的夹具，跑完必须在 `finally` 里还原**（`overview96` / `js_error_sweep` 都按"地表 2 人、洞穴 1 人"写断言）；**奇数位故意留一份三围为 `null` 的样本**，否则紧凑行把"采不到"画成 0% 也不会被抓到。判据也别只数第一行：`null` 出现在偶数位，第一行的 `unknown` 恒为 0。教训是**探针造的是"渲染后的 DOM"还是"驱动 DOM 的那份状态"，决定了它能不能验到条件分支**；条件一旦从 CSS 搬到 JS，旧的 DOM 探针不会报错，只会礼貌地一直通过。
